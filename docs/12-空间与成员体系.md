# 12 · 空间与成员体系（v3）

> 版本：config schema **v3**。在"账号即空间（v1/v2）"之上，把**账号 ↔ 空间**从一对一改成**多对多成员表**，引入**空间角色（owner / editor / viewer）**、**邀请码自助加入**、**普通账号配额建空间**与**审计日志**。
>
> 一句话区分两件事：
> - **角色**管"你进了这个空间之后能做什么"；
> - **邀请码**管"你怎么才能进到别人的空间"。
>
> 普通账号可以自助创建**属于自己的**空间（纯增量、受配额限制），但**加入他人空间必须持有有效邀请码**——不能凭猜测空间名加入，避免误入/擅入他人数据。

---

## 1. 数据模型（config.json v3）

顶层五段，`version: 3`：

```jsonc
{
  "version": 3,
  "accounts": {
    "alice": {
      "password": "pbkdf2$120000$<salt>$<hash>",   // 永不存明文
      "space": "main",                              // ★ 当前空间指针（同时只生效一个）
      "role": "admin",                              // 全局角色：admin | user
      "enabled": true,
      "space_quota": null,                          // null=跟随全局 max_owned_spaces；数字=该账号最多拥有几个空间
      "created_at": "2026-10-06T12:00:00",
      "updated_at": "2026-10-06T12:00:00"
    }
  },
  "spaces": {
    "main": { "name": "main", "kind": "shared", "created_at": "...", "created_by": "alice" }
  },
  "members": {
    "main": {
      "alice": { "role": "owner",  "joined_at": "...", "invited_by": "" },
      "bob":   { "role": "editor", "joined_at": "...", "invited_by": "alice" }
    }
  },
  "invites": {
    "Ab3kP9qT": {
      "space": "main", "role": "editor",
      "created_by": "alice", "created_at": "...",
      "expires_at": "...", "max_uses": 1, "uses": 0,
      "note": "给妈妈的手机", "disabled": false
    }
  },
  "policy": {
    "user_create_space": true,   // 普通账号可否自助建空间
    "max_owned_spaces": 3,       // 默认建空间配额（账号 space_quota 未设置时生效）
    "allow_self_register": true, // 是否允许凭邀请码自助注册新账号
    "member_invite": false       // editor 能否发邀请码（默认仅 owner）
  }
}
```

> **配额口径**：普通账号建空间受配额限制，**账号级 `space_quota`（0-1000，null=跟随全局）覆盖 `policy.max_owned_spaces` 默认值**；全局 admin 账号不限。配额只统计账号作为 **owner** 的空间数（editor/viewer 加入的不计）。`GET /api/me` 返回 `policy.my_quota`（null = 不限），管理员可通过 `PUT /api/users/{name}/quota` 给任意账号单独设配额。

### 不变量

1. 每个账号的 `space` 指针必须指向一个**存在的空间**，且该账号在其 `members` 中。
2. 每个**非孤儿空间至少有一个 owner**；移除/降级导致没有 owner 时，后端自动提升一名成员，或拒绝该操作。
3. 邀请码的 `role` 只能是 `editor | viewer`，**不能用邀请码直接造 owner**。
4. 空间 **id 稳定不变**（也是 pkl 文件名、WebDAV 地址语义），正则 `^[A-Za-z0-9_\-\u4e00-\u9fa5]{1,32}$`，禁止 `space__` 前缀与 `.`/`..`；**展示名 `name` 可改**（见 §3 重命名），与 id 允许不一致，API 路径参数由 `_find_space` 同时接受 id 或唯一展示名。
5. 密码一律 `pbkdf2$120000$...`，迁移与落盘都不二次哈希、不还原明文。

### 角色定义

| 角色 | 含义 |
|---|---|
| **owner** | 空间管理员：可读写、管理成员、发邀请码、删除仅含自己的空间 |
| **editor** | 可同步增删改、处理**自己提交的**待确认卡；`member_invite=true` 时可发码 |
| **viewer** | 只读：只能拉取歌单，不能 PUT、不能网页改删、不能处理卡、不能管成员 |
| 全局 **admin** | 不是空间角色而是账号全局角色；对**任何空间视同 owner**，且唯一能管理账号、代管空间、清理孤儿空间 |

## 2. v2 → v3 迁移

服务启动（`run_fastapi.load_config`）时检测 `version < 3`，自动迁移：

1. 为每个**被账号指向的空间**补 `spaces` 元数据（首个归属/创建该空间的账号决定 `kind`：仅自己用为 `personal`，多账号共用为 `shared`）。
2. 建 `members`：**空间的首个创建/归属账号即 owner**；之后指向同一空间的其它账号为 `editor`。
   - 不采用"同名即 owner、否则 editor，再给无 owner 空间兜底塞全局 admin"的做法——那会让 admin 成为所有空间的成员、账号删尽后空间永不孤儿。
3. 账号当前 `space` 指针原样保留；`invites` 为空；`policy` 取默认值。
4. 整份配置**原子写盘**（临时文件 + fsync + `os.replace`），并滚动保留 `.bak1` / `.bak2`；密码保持原 pbkdf2 串不变。
5. 迁移完成后旧 v2 行为（同步 GET/PUT、Basic 认证、老空间 `default` 的 `账号:方言` client key）完全不变（回归用例 `test_m8_legacy_client_key_compat` 覆盖）。

**孤儿空间**：没有任何成员、也没有账号指向，但磁盘上仍有 `space__<id>.pkl` 的空间。它不会被自动删除，只在全局 admin 的"空间管理"里列出，由 admin 显式删除。

## 3. HTTP 接口（均需 Basic 认证，除 /api/register）

### 身份与自助

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/me` | 当前账号身份：`{name, global_role, is_admin, space, my_role, spaces[], policy{}}` |
| POST | `/api/me/space` | 切换**当前空间指针**到自己已加入的空间；非成员 → 403；`space` 参数接受 id 或**唯一展示名**（C3，第四轮） |
| POST | `/api/me/leave` | 退出某空间；唯一 owner 拒绝（400），退出后自动切回个人空间；`space` 参数接受 id 或**唯一展示名**（C3，第四轮） |
| POST | `/api/register` | **无需登录**，凭邀请码注册新账号（受 `allow_self_register` 开关）；成功即加入码空间，不建个人空间 |

### 空间

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/spaces` | 成员看自己加入的；全局 admin 看全部（含 `orphan` 标记） |
| POST | `/api/spaces` | 普通账号受配额（默认 ≤3），建完即 owner 并可选择切为当前；admin 不限 |
| DELETE | `/api/spaces/{name}` | owner（且无其它成员）或全局 admin（含孤儿）；数据永久清除 |
| PUT | `/api/spaces/{name}/rename` | **空间 owner / 全局 admin**：改展示名（`body {"new_name": ...}`）；**id、pkl 文件名、WebDAV 地址、account.space 均不变**；重名/非法 400/409、幂等 200 不写审计、非 owner 403、不存在 404 |
| PUT | `/api/users/{name}/space` | **仅全局 admin**：把某账号代管分配到空间（同时维护成员表） |
| PUT | `/api/users/{name}/quota` | **仅全局 admin**：设置账号建空间配额（body `{"space_quota": n|null}`，n=0-1000，null=跟随全局） |
| PUT | `/api/policy` | **仅全局 admin**：修改全局策略（`member_invite` / `user_create_space` / `allow_self_register` / `max_owned_spaces`），写 `policy.update` 审计 |

### 成员

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/spaces/{name}/members` | 空间成员 |
| PUT | `/api/spaces/{name}/members/{account}` | owner / admin：改角色（editor/viewer，不能造/撤最后一个 owner） |
| DELETE | `/api/spaces/{name}/members/{account}` | owner / admin：移除成员，被移除者自动切回个人空间 |

### 邀请码

| 方法 | 路径 | 权限 |
|---|---|---|
| POST | `/api/invites` | owner（或 `member_invite=true` 的 editor）；参数 `space/role/expires_in_hours(1–720,默认24)/max_uses(1–100,默认1)/note(≤60)` |
| GET | `/api/invites?space=` | 该空间 owner / admin |
| DELETE | `/api/invites/{code}` | 创建者 / owner / admin：撤销 |
| POST | `/api/join` | 任意已登录账号，凭码加入；失效返回四种可区分文案：**不存在 / 已撤销 / 已过期 / 已用完** |

`GET /api/spaces` 与 `/api/me` 的每个空间条目（`_space_summary`）：

```jsonc
{
  "space": "main", "name": "main", "kind": "shared",
  "my_role": "owner",
  "members": [ { "name": "alice", "role": "owner", "joined_at": "...", "invited_by": "" } ],
  "playlists": 3, "revision": 12,
  "exists": true, "orphan": false, "is_current": true
}
```

## 4. 权限矩阵

| 操作 | viewer | editor | owner | 全局 admin |
|---|---|---|---|---|
| 同步 GET（拉歌单） | ✅ | ✅ | ✅ | ✅ |
| 同步 PUT / 网页改歌单 / 删歌单 / 改序 | ❌ 403 | ✅ | ✅ | ✅ |
| 确认/拒绝待办卡 | ❌ | 仅自己的卡 | ✅ 本空间任何卡 | ✅ |
| 生成邀请码 | ❌ | 仅当 `policy.member_invite` | ✅ | ✅ |
| 加/移成员、改角色 | ❌ | ❌ | ✅ | ✅ |
| 删本空间 | ❌ | ❌ | ✅（无其它成员） | ✅ |
| 新建空间 | ✅（受配额） | ✅（受配额） | ✅（受配额） | ✅ 不限 |
| 空间管理（孤儿空间、账号代管） | ❌ | ❌ | ❌ | ✅ |

> viewer 也允许"新建自己的空间"——那是对其**自己空间**的写，不涉及他人数据。

### viewer 的只读拉取（引擎配套）

合并引擎的 `deliver` 对"从未 PUT 建立基线"的客户端返回 404（M1 防丢数据保护），而 viewer 不能 PUT，会永远拉不到。为此 `SyncSpace` 新增**纯只读**方法 `peek_view(dialect, can_delete)`：

- 用一个**不注册进 clients** 的临时客户端调 `render_for`；
- **不推进基线、不写 journal、不改 revision**，零状态变更（D34 后无墓碑/确认水位/GC 概念）；
- API 层对 `my_role == "viewer"` 的同步 GET 走 `peek_view`，且 opaque 返回空（viewer 看不到他人私有主题/音源配置）。

这是"不动引擎合并语义"铁律下唯一的只读例外。

## 5. 审计日志

- 落盘：`<store_dir>/_audit.jsonl`，一行一条 JSON：`{ts, action, actor, space, detail}`。
- 只依赖 hub 存储目录、不依赖 config_path，因此测试环境也落盘。
- 覆盖：建/删空间、加/移/改成员、生成/撤销/使用邀请码、自助注册、切换/退出空间、管理员代管改空间。
- `GET /api/state` 尾部返回最近 30 条 `audit`，前端同步日志可见"哪个账号、在哪个空间、做了什么、什么时间"。

| 空间级主题/音源默认值共享 | opaque 已按客户端分桶，够用 | `spaces[*].opaque_default` |

## 7.1 空间重命名（第三轮）

- **方案**：展示名（`spaces[id].name`）可变，**空间 id 不变**。id 是 pkl 文件名与 WebDAV 地址语义，改名不动任何数据文件；`account.space` 仍存 id，不得改 name。
- **解析规则**：新增 `_find_space(token)`——先按 id 精确命中（永远有效），否则在全部空间的 `name` 中唯一命中；`DELETE /api/spaces/{name}`、成员三路由、`PUT /api/users/{name}/space`、邀请码路由、rename 路由统一走它，因此 id 与展示名都可作为路径参数。
- **输出**：`/api/state` 带 `name`、`/api/me` 带 `space_name`，members 列表带 `space_name`、invites 每行带 `space_name`；前端统一用「展示名，回退 id」显示（`spaceLabel` / `spaceName`）。
- **校验**：非法名 400；与任何 id 或展示名冲突 409；new_name == 当前 name 幂等 200（不写审计）；非 owner 403「仅空间管理员可重命名」；不存在 404。
- **不变量**：id / pkl 文件名 / 客户端地址零变化；同步照常（test_23：改名后 bob 照常 GET、alice 照常写入）。

## 8. 上公网前必做（安全）

邀请码与自助注册**只能在可信网络直接开放**。上公网前必须：

1. 首登强制修改默认 `admin/admin123`；
2. 对登录、`/api/join`、`/api/register`、Basic 认证做**限流 / 失败计数 + 退避**（防爆破与枚举邀请码）；
3. HTTPS（反代或隧道）；
4. 公网部署关闭 `allow_self_register` 或收紧邀请码策略；
5. 常驻自启、定时异地备份、日志轮转。
