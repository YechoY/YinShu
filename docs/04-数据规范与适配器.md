# 04 · 数据规范（canonical-v1）与适配器

## 4.1 为什么需要内部规范

各客户端格式不同，但都在表达同一件事：**一组歌单，每个歌单里有一组歌曲**。枢纽内部只维护**一份**统一表示，于是：

- 新增平台 = 加一个适配器，**不动**已有平台；
- 合并算法只写一次，不随平台数量增长；
- 合并结果可以导出成人可读的 JSON，用于审计、备份、回滚。

**规范全文见** [`../spec/canonical-v1.md`](../spec/canonical-v1.md)；机器可校验版本 [`../spec/canonical-v1.schema.json`](../spec/canonical-v1.schema.json)；示例 [`../spec/examples/canonical-v1.example.json`](../spec/examples/canonical-v1.example.json)。

```bash
# 校验（仅需 Python 标准库）
python spec/validate-canonical-v1.py spec/examples/canonical-v1.example.json
# → 0 错误 / 1 警告（未登记品质码原样保留，符合 E-QUAL 扩展规则）
```

本节只做摘要与"怎么接"。

## 4.2 canonical-v1 摘要

| 部分 | 内容 |
|---|---|
| 顶层 | `schemaVersion`, `generatedAt`, `space`, `playlists[]`, `tracks[]`（曲目池）, `tombstones[]`, `ext{}` —— **字段名一律以 `spec/canonical-v1.md` 为准**（评审 S5：本文件曾与 spec 各写一套命名） |
| 歌单 | `id`（枢纽分配，稳定）、`name`、`cover`、`createdAt`、`updatedAt`、`trackIds[]`（稳定顺序 = 枢纽设定的 canonical 顺序）+ 平台别名表 |
| 曲目 | 记录键 `id`（`tr_<ULID>`，仅作引用）；**身份键 = `(source, songId)`**；同一身份在池中只允许一条记录，**多个歌单引用同一条不违反唯一性**（评审 S4 澄清：原"身份唯一 vs 多歌单共用"并非冲突） |
| 平台码 | `wy / tx / kw / kg / mg / ...`（与栖弦 `enums.dart:3-7` 对齐，未知码原样保留）；`lx`（LX 本地/自定义源）**待 M0.5 取证后登记**（评审 N5） |
| 品质 | 规范码 + 排序（`master > atmos_plus > atmos > hires > flac24bit > flac > 320k > 192k > 128k`），各平台原生码由适配器映射 |
| 墓碑 | `{element: playlist\|track, id, deletedAt, origin}` —— **删除是一等公民**，不靠"缺席"表达；`track` 墓碑按**身份键**记录（非 `tr_<ULID>`） |
| 扩展 | 命名空间 `ext.<vendor>.*`：未知字段**原样保留**，保证新老版本互不破坏（E1–E6） |
| 兼容 | 未知品质码/未知音源/未知字段 → 保留不报错；规范版本只增不改语义 |

**三个不变量**：

1. **身份不靠名字**：曲目靠 `source+songId`，歌单靠枢纽分配的 id + 平台别名表（改名不产生新歌单）。**别名匹配只在"新建"时使用一次**：名字重复/为空时不得自动合并（评审 N6：防误合并"我的喜欢"这类空名歌单）。
2. **删除必须显式**：任何"消失"都要有墓碑，否则视为"尚未同步"。
3. **未知即保留**：识别不了的东西原样存，宁可不同步也不丢弃。
4. **客户端私有内容必须 round-trip**（评审 S2）：本地文件曲目、无平台 id 的兜底曲目、未知扩展字段一律进 `ext.<client>.opaque`，**不参与**合并判定与去重、**不参与跨设备交付**：按 `client_key` 分桶存储与渲染（2026-10-06，D23），`render()` 原样回填本客户端那份。否则栖弦 `applyFromSync`"缺席即删除"会把用户的本地音乐删掉，且绕过安全阀。

## 4.3 适配器契约

每个客户端方言实现同一组接口（纯函数，无副作用）：

| 接口 | 输入 → 输出 | 要求 |
|---|---|---|
| `fingerprint(payload, path, ua)` | → 置信度 0..1 | 用于"不认识路径时"的内容探测 |
| `parse(payload)` | → `CanonicalView` + 警告列表 | 结构坏了要**抛错**而不是猜；空歌单合法 |
| `render(view)` | → 该客户端格式的 payload | 必须满足**该客户端字段硬要求**（缺字段它就会崩） |
| `clientIdentity(path, ua, headers)` | → `{path_part, device_part, ua_family}` | **必须能区分同一 App 的两台设备**。**已实现（2026-10-06）**：`api.client_identity` —— 优先 `X-Hub-Device` 头，其次 URL 设备段 `/d/{device}/`，都没有则 `default`（老空间沿用 `账号:方言` 旧 key，行为零变化）；设备名限 `[A-Za-z0-9_-]{1,32}`，非法 400。**未采用**"缺失则枢纽签发"与 `Client-Id`（栖弦不发头；签发需要客户端回显，本阶段不可用，docs/11:74-76 建议不采纳） |
| `capabilities()` | → `{deleteTrack, deletePlaylist, createPlaylist, reorder, ...}` | 告知"这一端能不能执行某类变更" |
| `limits()` | → `{maxBytes, maxItems, encoding}` | 用于安全阀与截断防护 |

**渲染硬要求示例（cyshine-v1）**：`schemaVersion: 1`、三节 `sections{playlists,appearance,musicSources}` 缺一不可、`appearance.data.themeSeedArgb` 必须是 JSON **整数**、`data` 必须是**数组**、`version: 1`、时间用 ISO-8601 字符串、`musicInfo.meta.songId` 必须回填（否则身份丢失）、`interval` 形如 `03:27`（零填充）；**响应只允许 2xx**——栖弦对 `304`/非 2xx 一律抛"WebDAV 请求失败"（`webdav_client.dart:69/91`），所以内容未变也必须返回 `200` + 相同正文与相同 ETag。

## 4.4 逐客户端映射

### 4.4.1 `cyshine-v1`（栖弦）

| canonical | cyshine | 备注 |
|---|---|---|
| 歌单 `id` | `playlists.data[].id` | 枢纽分配后回填；缺失则新建并把名字作为别名 |
| `name` | `.name` | **不靠名字对齐**，只作首次匹配的别名 |
| `createdAt/updatedAt` | `.createdAt/.updatedAt` | ISO 字符串 |
| section 时间 | `sections.playlists.modifiedAt` | 随空间 revision 单调推进，**内容不变则不推进**（评审 S3：原"永远填当前时间"会导致每轮都被判远端更新 ⇒ 写放大 + 覆盖本地未同步新增） |
| 曲目身份 | `musicInfo.meta.songId` + `musicInfo.source` | 优先 `meta.songId`，否则从 `musicId` 去 `${source}_` 前缀 |
| `musicId` | `${source}_${songId}` | 渲染时必填 |
| `quality` | 原生码 | 规范码 → 原生码映射表 |
| `interval` | `03:27` | 由 `durationMs` 生成，零填充 |
| `themeSeedArgb` 等 | `appearance` 节 | 枢纽**不参与**其内容，仅原样透传/整段 LWW |
| 未知字段 | — | 保留在 `ext` 中，渲染时回填 |

### 4.4.2 `lx-v1`（LX Music）· 待研究

M4 前必须取证：**配置项（地址/账号/路径）、文件名与目录结构、数据格式、使用的方法（GET/PUT/是否 PROPFIND）、是否条件写、时间戳语义**。适配器契约已就绪，补上即可接入。

### 4.4.3 `ceru-plugin`（澜音插件）· 可选

插件继续写它自己的文件；枢纽为其提供适配器，或让其直接调用枢纽的 REST 接口（插件 HTTP 方法不受限）。由于 SDK 缺"删歌/建歌单"能力，其 `capabilities().deleteTrack = false`，枢纽渲染时把"本地应删的歌"放在**待清理清单**（不静默丢弃）。

## 4.5 未知方言：隔离降级（决策 D11）

```text
PUT /sync/<space>/<任意路径>
  1) 路径匹配已知路由？ ── 是 → 对应适配器
  2) 内容指纹 ≥ 阈值？   ── 是 → 对应适配器
  3) 否则 → 隔离容器
       · 原样保存（该端 GET 仍得到它自己那份，功能不坏）
       · 记录发现事件（路径、UA、顶层字段指纹、样例片段）
       · 不参与跨格式合并
       · 事后补适配器 → **先通知用户、经其确认后**并入空间（评审 M3：否则用户只会觉得"配置对了却什么都没发生"）
```

**为什么必须这样**：错误格式的"合并"等于随机丢数据。隔离只损失"暂不同步"，不会损失数据。

## 4.6 规范演进

| 场景 | 做法 |
|---|---|
| 客户端升级换了格式（如 `cyshine-v2`） | 新增适配器版本，`v1`/`v2` 并存；按指纹路由 |
| 规范自身升级 | `schemaVersion` 递增；只在**语义增量**时升级；旧 `v1` 文档必须仍可解析 |
| 未知音源/品质码 | 原样保留 + 警告；不阻塞同步 |
| 字段废弃 | 先停写、后停读，至少跨一个版本 |
