# 08 · 风险与开放问题

## 8.1 风险登记表

| # | 风险 | 概率 | 影响 | 缓解 | 触发时的退路 |
|---|---|---|---|---|---|
| R1 | 合并语义有洞（误删/复活） | 中 | **高（丢数据）** | M1 PoC **26 条**用例 + 安全阀（挂起而非整批拒绝）+ 首轮只增不删 + `base_served` 差分（I2′）+ 墓碑确认水位 GC（D21） | journal 回放 + 备份恢复；每个事故变一条回归用例 |
| R2 | 客户端身份不稳定（换机/清数据/UA 变化） | 高 | 中 | 新身份一律"只增不删"；保留旧基线 30 天；全量身份突变告警 | 手动合并基线 |
| R3 | WebDAV 兼容层不满足某客户端 | 中 | 中（不工作） | 逐客户端真机验证；保留 `501` 降级；怪癖登记表 | 针对该客户端补协议细节或退回形态 B |
| R4 | AList 忽略 `If-Match` 导致并发覆盖 | 中 | 中 | 单写者事务 + 每客户端基线差分 + 抖动重试 | 最坏多同步一轮，不丢数据 |
| R5 | 密码错误锁定服务器 IP（AList 6 次/IP/30 min） | 中 | **高（全体不可用）** | 本地失败限流（≥5 次直接拒）+ 成功缓存 + 专用校验账号 | 换隧道出口 IP / 临时改用乙方案账号 |
| R6 | 单文档过大/写截断 | 中 | 中 | 文档硬上限 1 MiB / **工程目标 ≤100 KB**、gzip、**写后自校验**、**绝不裁剪曲目** | 拒绝写入并保留原文件 + 状态页提示导出；超 800 KB 触发分片设计 |
| R7 | LX（或未来客户端）格式复杂/私有 | 中 | 低 | 先隔离不参与合并；适配器按需补 | 该平台仅"可读写不互通" |
| R8 | 服务长期无人值守出故障 | 中 | 中 | 健康检查 + 告警 + 自动重启 + 备份 | 客户端本地数据不受影响 |
| R9 | 用户误操作（手动删光歌单） | 低 | 中 | 安全阀 + 确认通道 + 回滚 | 备份/journal 恢复 |
| R10 | 平台 SDK 缺口（澜音无删歌/建歌单） | 高 | 低 | 该端标记"待清理清单"，不静默丢弃；不影响枢纽一致性 | 等上游 API 或降级为手动 |
| R11 | 隐私与凭据泄露 | 低 | 中 | HTTPS、只存哈希、日志脱敏、独立同步密码、可吊销 | 吊销账号 + 轮换 |
| R12 | 范围膨胀（把本项目做成通用云盘同步） | 中 | 中 | 明确"只做歌单"；不做文件同步/播放器 | 回到 V1–V10 验收口径 |
| R13 | **客户端"相等则不写回"**（栖弦 `webdav_sync_controller.dart:286`）⇒ 该端**自己的删除**在某些轮次不传播 | 中 | 低 | 已记为 `docs/05` §5.6 已知限制；切前台/手动同步会带上删除；M0.5 取证后决定是否补"墓碑确认" | 状态页显示"该设备上次提交时间"，提醒手动同步 |
| R14 | **无基线客户端的 GET 语义**（新设备先 GET 后 PUT 可能被"缺席即删除"清一次） | 中 | 中 | **已由源码判定**（`docs/03` §3.5.1）：栖弦必先 GET（`webdav_sync_controller.dart:259-296`）⇒ 无基线客户端 GET **必须 404**，条件写头不符也**不回 412**；M0.5 只做真机复验 | 从备份/journal 恢复 |
| R15 | **认证单点**：甲方案下 AList 不可用 ⇒ 全体无法认证且无降级 | 中 | 中 | 校验结果短期缓存（60–120 s）+ 只读降级（缓存期内允许已认证会话继续读）；告警 | 切换乙方案（自管账号） |
| R16 | **墓碑压制误伤合法重加**：用户**换设备后**带来一张含已删条目的旧副本时，会被"待确认恢复"卡拦一次（D20/D21 的唯一代价；**同身份设备与已确认过的身份不受影响**） | 中 | 低 | 确认卡写清原因（"你于 X 删过它"）+ 一键恢复 | 状态页一键恢复；**不得**用"缩短 TTL"缓解——那会重新打开复活窗口（D21） |

| Q13 | 真实云端的单文档上限（AList 截断阈值的复现与边界）？ | 文档预算与分片触发点 | 隧道恢复后 |
| Q14 | AList 多用户 WebDAV 的实测行为（Basic 校验、`Depth:1`、路径隔离、条件写是否被忽略）？ | 甲/乙方案选型（= Q2） | 隧道恢复后 |
| Q15 | ~~LX Music 的 WebDAV 配置项/路径/格式/方法？~~ → **已决**：不做 LX（与 Q1 一并取消，D18） | — | — |
| Q16 | 用户是否真的需要"共享空间"？ | 数据模型（= Q4） | **已决（2026-10-05）：不做**。**已于 2026-10-06 反转（D23）**：支持共用空间（多账号同一 `space_id`）；删除归因由安全阀 + `never_owned` 卡 + `account` 归属解决 |
| Q17 | **能否用 `ETag` 当"交付句柄"来自动区分同一路径后的多台设备？** 栖弦写回时必带 `If-Match: <上次 GET 拿到的 ETag>`（`webdav_client.dart:83`、`webdav_sync_controller.dart:288`）；若枢纽**每次交付发一个唯一 ETag**，则该 ETag 即"哪一次交付"= 一条基线的句柄 ⇒ 两台设备各持自己那份 ⇒ 枢纽顺着 ETag 就能认出两条基线，**客户端零改动、用户零配置**，D10 的残差消失。代价/冲突：① 与 `PF4`"内容不变返回相同 ETag"冲突，需专门定 ETag 语义；② 首次接入走 `If-None-Match: *`（`createOnly`）时无句柄可用；③ AList 忽略 `If-Match` ⇒ 若门面透传到 AList 则拿不到句柄，必须在门面层自行签发与校验 | 消除 D10 唯一残差（同地址多设备小比例误删） | M0.5/M1 一起验证；**验证通过前 D10 严格按现状执行** |
| Q18 | **空间改名 / 稳定 space_id（v3，D24）？** 空间名当前即 `space_id`，也是 pkl 文件名（`space__<id>.pkl`）与 WebDAV 地址语义，"改名"等于物理搬迁 + 所有客户端换地址。**已于第三轮（2026-10-06）落地**：`spaces[*].name` 作为展示名（可变、允许重名），`id` 稳定不变、`account.space` 仍存 id，API 路径参数由 `_find_space` 同时接受 id 或唯一展示名，WebDAV 地址不含空间名故客户端零影响。账号重命名不影响空间名（空间名不随账号改） | 空间可改名、允许重名 | 已落地（第三轮 rename/policy 路由） |
| Q19 | **限流与防爆破（v3，D24）？** 邀请码为 8 位字符集、`/api/join`/`/api/register` 与 Basic 登录当前**无限流**，直接暴露公网会被枚举邀请码、爆破口令。**本期定位本机/可信家庭网络，不实现**；上公网前必须加按 IP/账号的失败计数 + 指数退避 + 临时锁定、首登强制改默认 `admin/admin123`、关闭 `allow_self_register`、上 HTTPS（见 docs/06 §6.3、docs/12 §8） | 公网部署安全 | 上云/公网暴露前（P0 安全项） |

## 8.3 依赖与假设

| 依赖 | 说明 | 不成立时的后果 |
|---|---|---|
| 客户端允许自定义 WebDAV 地址 | 栖弦/AList 系客户端满足；LX 待确认 | 该客户端只能 fork 或放弃 |
| 本机常开 + 隧道可用 | 用户现状（AList + 内网穿透） | 同步暂停，不丢数据 |
| 客户端按标准 WebDAV 交互 | 栖弦满足；个别客户端可能用私有扩展 | 该客户端需单独适配 |
| 用户接受"分钟级"而非实时 | 已确认（D1） | 若要求实时，需另加推送通道（超出本项目边界） |
| 真实数据可先备份再演练 | 由用户执行/授权 | 无备份**不得**接入真实数据 |
