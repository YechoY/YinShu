## 2. `spec/`：对外契约（写给"接新客户端的人"看）

- [canonical-v1.md](spec/canonical-v1.md) + [canonical-v1.schema.json](spec/canonical-v1.schema.json)：内部统一格式的规范与 Schema

## 3. `notes/`：实现过程的历史留档（**不是现状**）

各轮"给豆包的修改文档"、复核报告、一次性方案都在这里。它们是往返记录，用于追溯"当时为什么这么改"；结论可能已被后续轮次覆盖，**以 09-决策记录为准**。
最近一轮是 `notes/第六轮开发计划.md`（适配器插件化、洛雪接入、设备身份、栖弦枢纽模式需求单）。

早期方案 v0、前身"真正同步方案"、设计说明书 v1、旧 stdlib HTTP 入口。仅作考古。

## 文档 ↔ 代码对应关系

| 想知道… | 看代码 |
|---|---|
| 合并/删除/墓碑/时间戳怎么算 | `src/engine/engine.py`、`src/engine/canonical.py` |

| 引擎用例 | `tests/engine/` |
| 服务/HTTP 用例 | `tests/hub/` |

## 常用命令

```bash
uv run python -m hub.run_fastapi --host 0.0.0.0 --port 8000   # 启动枢纽（局域网联调）
uv run pytest                                                  # 全量测试（逐模块跑更稳，见 README）
cd webui && npm run build                                      # 前端构建到 webui/dist
```
