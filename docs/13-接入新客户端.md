# 13 · 接入新客户端（适配器插件化）

> 本文件回答"**接一个全新客户端**要做什么"。结论先行：**新增客户端 = 新增一个适配器文件**，枢纽的 `api.py` / `store.py` / `engine.py` **零改动**。
> 对应代码：`src/hub/adapters/`（第六轮 §1 适配器插件化，2026-10-07）。

## 13.1 为什么是"加一个文件"

枢纽内部只维护一份 canonical 视图，各客户端格式由适配器负责双向翻译。第六轮把适配器从 `src/hub/adapters.py`（单文件手写路由表）重构成 `src/hub/adapters/` 包 + **自动发现注册表**：

- 新方言 = 在 `src/hub/adapters/` 下新建 `<名字>.py`，模块级导出 `DIALECT`；
- `adapters/__init__.py` 用 `pkgutil` 自动发现，拼出 `REGISTRY` 与 `CAPABILITIES`；
- 路由由 `api._register_dialect_routes()` 循环注册，`_sync_get` / `_sync_put` 统一走 `REGISTRY[dialect].parse / render`；
- 引擎侧通过 `SyncSpace.set_known_dialects(REGISTRY 键集合)` 注入白名单（`engine.py` 内建默认保留 `cyshine-v1` / `ceru-plugin`，只作"引擎单测直接 import 不加载 hub 时"的兜底）。

**验收硬指标**：`rg "cyshine-v1|ceru-plugin" src/hub/api.py src/hub/store.py` 必须 **0 命中**；`src/engine/engine.py` 仅剩 2 处**给引擎单测直连 import 用的内建兜底**（`:44` 注释、`:90 KNOWN_DIALECTS` 默认值、`:125 register_client` 默认参数），它们在 hub 导入时必定被 `set_known_dialects(REGISTRY)` 覆盖，**不参与运行时判据**。真正的硬指标是"**加客户端不改枢纽任何文件**"（含 engine.py）——今天已经做到。

## 13.2 Dialect 字段一览（`src/hub/adapters/base.py`）

| 字段 | 类型 | 含义 |
|---|---|---|
| `name` | str | 方言名，如 `lx-x`；同时是 URL 路径段（`/lx-x/playlists.json`） |
| `roots` | tuple[str, ...] | 命中的根目录段（如 `("lx-x",)`） |
| `files` | tuple[str, ...] | 该客户端使用的文件名（如 `("playlists.json", "settings.json")`） |
| `parse(payload)` | fn | 客户端格式 → `CanonicalView` + 警告；结构坏抛 `ParseError` |
| `render(view)` | fn | canonical → 客户端格式；必须满足该客户端字段硬要求 |
| `capabilities` | dict | `delete_track / delete_playlist / create_playlist / reorder` 等 |
| `empty_view_on_no_baseline` | bool | 无基线时 GET 返回 200 + 空视图（True）还是 404（False） |
| `file_fallback` | bool | 允许 WebDAV 兜底路由按文件名分派（True 时 `/d/{device}/` 前缀也生效） |
| `deliver_ack_on_view` | bool | "看过 = 已采纳"：**True = 栖弦 / 洛雪**这类拿到视图即整份替换的客户端，交付视图时就 ack 墓碑；**False = 澜音**（删不掉本地、看过必带回），删除确认只来自"这次提交里确实没有该键"。见 `adapters/base.py:91-93`、`engine.py:360-369`（ack 门在 `engine.py:369`） |
| `bypass_files` | tuple[str, ...] | 整文件旁路（不合并、原样存、原样还），如洛雪 `settings.json` / `user_apis.json` |

## 13.3 接入步骤（以洛雪 `lx-x` 为范例，见 docs/14）

1. **读真机文件**：拿到该客户端真实的歌单文件（本地/云盘副本），统计结构、字段、样本分布；不要凭印象写适配器。
2. **建 `src/hub/adapters/<名>.py`**：实现 `parse` / `render` 与 `DIALECT`。要点：
   - 身份键：`(source, songId)`——从该客户端"最能标识一首歌"的字段取（如洛雪顶层 `id` 去 `<source>_` 前缀）；
   - 无法定身份 / 非白名单音源 → 进 `opaque["tracks"][歌单id]`，**不参与合并判定与去重**；
   - 未知字段原样保留（`ext.*` 与 opaque 分桶），宁可不同步也不丢弃。
3. **旁路文件**（该客户端需要但不要合并的文件）：写进 `bypass_files`；`api._sync_get/_sync_put` 走 `rt.opaque_by_client[cid]["<名>_blobs"]` 原样收/还。
4. **测试**（`tests/hub/test_adapters_<名>.py`）：parse 统计（分布、opaque、旁路）、身份规则、render 外形、WebDAV 路由往返、幂等。**新增测试须可证明语义**，不许放宽既有断言。
5. **跑回归**：`tests/hub` 全量 + `tests/engine` 全量（逐模块跑；本机有"端口残留 + 全局 api 单例"假失败坑，HTTP 测试类端口基址互不相同，见各文件 `cls.port`）。

## 13.4 设备身份（多设备必读）

同账号 + 同客户端 + 不报设备名 = **同一台设备**（共享一份同步基线，A 没同步到的新歌会被 B 判成"删除"）。因此**多设备必须各报设备名**：

- 请求头 `X-Hub-Device: <设备名>`（**首选**；设备名 `[A-Za-z0-9_-]{1,32}`，非法 400）；
- 或 URL 设备段 `/d/<设备名>/...`（兜底）；
- **头优先于路径段，二选一不要叠加**。

详见 `docs/notes/客户端对接说明.md` §0。
