# 07 · 路线图与验收用例

## 7.1 阶段划分（每个阶段都有独立价值、都能停）

| 阶段 | 目标 | 交付物 | 完成定义（DoD） | 是否碰真实云端数据 |
|---|---|---|---|---|
| **M0 设计冻结**（当前） | 一套完整、可评审、可扩展的设计 | 本目录全部文档 + `spec/` | 专家评审通过；开放问题已登记 | 否 |
| **M0.5 事实补采** | 打通未知项 | AList 多用户实测报告（LX 取证已取消，D18） | 隧道恢复后实测：栖弦 GET/PUT 顺序、`MKCOL` 父目录行为、`409/507/429` 行为 | 只读 |
| **M1 合并引擎 PoC** | 证明"不丢数据" | 纯逻辑实现 + **26 条边界用例全绿** | 用例全绿；故障注入（坏 JSON、并发、安全阀挂起、`base_served` 语义、墓碑压制）通过 | **否**（合成数据） |
| **M2 本机门面 + 接栖弦** | 证明"零改动可接"（**不是**"真实双向"——第二个参与者还没有，评审 I2） | 本机 WebDAV 门面；栖弦只改地址即同步；**第二个参与者**（澜音插件或第二个栖弦实例） | 栖弦 ↔ 门面 ↔ 第二参与者真实双向；协议用例（`curl` 逐项打 OPTIONS/PROPFIND/GET/PUT/MKCOL/MOVE/412）全过；**仍然不接真实云端**（用副本数据） | 用副本 |
| **M3 搬到隧道 + 多用户** | 证明"一个 URL + 账号密码"可用 | 反向代理 + AList 认证复用 + 限流 | 两个账号交叉验证隔离；失败锁定防护生效 | 是（小范围） |
| ~~**M4 LX 适配器**~~ | **已取消**（D18：用户只要栖弦 + 澜音） | — | — | — |
| **M5 澜音接入** | 澜音加入（**形态 M5 再定**：插件 REST 或 WebDAV 适配器二选一，D18） | 插件适配或 REST 接入 | 澜音增删双向；"待清理清单"可见 | 是 |
| **M6 加固与上线** | 敢长期无人值守 | 备份/监控/配额/文档/回滚演练 | 恢复演练通过；告警可用；运维手册就绪 | 是 |

**顺序理由**：合并语义（错就丢数据）> 协议兼容（错就不工作）> 部署（错了能重启）。所以 M1 先把"语义"钉死，M2 再碰真机协议。

## 7.2 关键里程碑检查点

| 检查点 | 通过标准 |
|---|---|
| G1（M1 后） | **26 条**边界用例全绿；同一请求重复执行结果一致（幂等）；安全阀在 80% 删除时**挂起删除并正常交付**（数据无损）；墓碑压制（I7）用例 26 通过 |
| G2（M2 后） | 栖弦真机：加歌/删歌/加歌单/删歌单 4 个动作，**对端 = 第二个参与者**，5 分钟内一致；**没有任何一次数据丢失**；协议用例全过。**判据**：若 3 天内无法让栖弦稳定通过 `MKCOL`/`412`/大小限制三项，则退回**形态 B（守护进程 + 客户端继续直连 AList）**，不硬扛（评审 I6） |
| G3（M3 后） | 两个账号互不可见；连续 5 次错密码只影响该账号，服务器 IP 未被 AList 封禁 |
| ~~G4（M4 后）~~ | **已取消**（D18）。LX 若将来重启，判据恢复为"格式不同但歌单一致；一方删除在另一方消失且不复活" |
| G5（M6 后） | 演练：删库 → 恢复 → 数据完整；演练：误删 50% → 安全阀**挂起**且可在状态页确认/回滚；**上线切换 SOP**（双写窗口、先备份、回退步骤）已演练（评审 I6/N3） |

## 7.3 验收用例（14 条主用例 + 7 条评审新增，与 V1–V10 对应）

| # | 用例 | 对应 | 通过标准 |
|---|---|---|---|
| A1 | 一端加歌，另一端分钟级出现 | V1 / V4a | 另一端可见；**顺序不作要求**（评审 I7） |
| A2 | 一端删歌，另一端消失且不复活 | V1 / I3 | 多轮同步后仍不存在 |
| A3 | 一端加歌单，另一端出现 | V2 | 歌单与曲目都在 |
| A4 | 一端删歌单，另一端消失 | V2 | 不复活 |
| A5 | 两端各自加不同歌 | V3 | 并集 |
| A6 | 两端各自删不同歌 | V3 | 两首都不存在 |
| A7 | 一端加 + 另一端删同一首 | V3 / I3 | 最终不存在（删除优先） |
| A8 | 首次接入一个已有数据的空间 | V7 / D8 | 只增不删，空间数据不减少 |
| A9 | 客户端清数据重装后再同步（**新身份**） | V7 / **V10** / I7 | 不血洗空间；已删条目**不复活**（转"待确认恢复"卡，用例 26） |
| A10 | 坏 JSON / 截断的上传 | V7 | 被拒且基线不动，其它端不受影响 |
| A11 | 删除 80% 曲目 | V7 / I5 | 安全阀**挂起删除**、新增照常应用、响应 200、数据无损、状态页出现确认卡 |
| A12 | 未知格式客户端接入 | V5 | 它自己能读写；不污染其它端；记录发现事件；状态页告知"正在识别格式" |
| A13 | 两个账号交叉访问 | V6 | 互不可见 |
| A14 | 故意杀死进程/断网/断隧道后恢复 | V7 | 无不一致、无丢失，自动收敛 |
| A15 | **本地文件曲目 round-trip**（`musicInfo == null && isLocal`） | V7 / I6 | 原样保留，不被任何一端删除（评审 S2） |
| A16 | **同一 App 两台设备**交叉增删 | V7 / I2′ | 互不误判删除（评审 S3） |
| A17 | **三客户端交错 GET/PUT** | V7 / S1 | 无删除、无重复并入、`revision` 不无限增长 |
| A18 | **退出枢纽回退直连原 WebDAV** | 迁移可逆（D14） | 数据完整、客户端无需改地址以外的操作（评审 I6） |
| A19 | **上线切换 SOP**（双写窗口、先备份再迁移、回退） | V7 | 演练通过，无分叉（评审 I6/N3） |
| A20 | **状态页可解释**（V8 走查） | V8 | 非技术用户 30 秒内答出"上次同步做了什么 / 有没有要我决定的事" |
| A21 | **误删恢复 3 次点击**（V9） | V9 | 状态页确认 → 回滚 → 验证，全程 ≤ 3 次点击 |
| A22 | **两个账号指向同一空间 → 歌单互通** | V11 / D23 | A 加歌/歌单，B（同空间）分钟级可见；双向删除自动生效；各自密码独立、可单独吊销 |
| A23 | **同空间两账号的 opaque 互不覆盖** | V11 / D23 | 两账号（或同账号两设备段）各自提交主题/音源/本地音乐 → 各自 GET 只见自己那份，互不顶掉 |
| A24 | **非本人提交的待确认卡**：确认/拒绝 403 | V11 / D23 | 普通账号 B 对 A 的卡操作 → 403；本人或管理员可操作 |
| A25 | **删除空间最后一个账号** → 空间数据默认保留 | V11 / D23 | 删号返回 `space_kept=true`、pkl 仍在；`?purge=true` 才 `space_deleted=true` |
| A26 | **v2 配置无感升级 v3 且不破坏同步**（D24） | V12 | v2 两账号两空间启动 → 当前空间指针不变、同步 GET/PUT 行为一致、同名/首个归属账号为 owner、落盘 version=3 且有 .bak |
| A27 | **自助建空间 + 配额 + 名校验**（D24） | V13 | 普通账号建空间即成 owner 并切为当前；建满 `max_owned_spaces`(=3) 再建 409、admin 不限；空名/`../`/`space__x`/重名 400/409 |
| A28 | **角色矩阵与 viewer 只读**（D24） | V12 | viewer 同步 GET 200（无需先 PUT，走 peek_view）、同步 PUT 与网页删歌单/曲目、确认卡全部 403；editor 可写、仅确认自己的卡；owner/admin 放行 |
| A29 | **邀请码加入互通 + 四种失效 + viewer 码**（D24） | V13 | owner 发码、另一账号 join 后同空间歌单互通；不存在/已撤销/已过期/已用尽分别 400 且文案可区分；role=viewer 码加入后 PUT 403 |
| A30 | **凭码注册 / 退出 / 切换 / 唯一 owner 保护 / 移除成员**（D24） | V13 | 新名+有效码注册即入空间，重名 409、坏码 400、关注册 403；leave 后回个人空间，切到非成员空间 403；唯一 owner 退出/被降级 400；owner 移除成员后其指针重置、对原空间 PUT 403 |
| A31 | **删空间约束 + 审计落盘**（D24） | V12/V13 | 有其它成员时删空间 400 并列出成员，移除后 owner 可删，孤儿空间仅 admin 可删；建空间/邀请/加入/移除在 `_audit.jsonl` 有记录且 `/api/state` 返回尾部 |

## 7.4 测试策略

| 层 | 手段 | 覆盖 |
|---|---|---|
| 单元 | 合并引擎纯函数测试（**26 条**边界） | 语义正确性 |
| 契约 | 每个适配器：真实样本 round-trip（`parse(render(x)) ≈ x`） | 格式保真 |
| 集成 | 内存 SQLite + 假客户端并发/乱序/重复请求 | 事务、幂等、串行化 |
| 协议 | `curl`/脚本逐项打 `OPTIONS/PROPFIND/PUT/MKCOL/MOVE/...`。**执行时机从"M2 之后"提前到 M2 第一天**（协议不通过 = M2 直接无法开始，评审移动端意见） | WebDAV 兼容层 |
| 真机 | 栖弦（Android）、澜音（M5，可选） | 端到端 |
| 回放 | 用历史真实数据（`歌单样例/sync-v1.json` + 澜音 `playlists.db` 导出）做演练 | 真实规模与脏数据 |
| 故障注入 | 断网、半包、截断、杀进程、磁盘满、并发写 | "不丢数据"底线 |
| 回归 | 每个真实事故 → 一条常驻用例 | 防止重犯 |

**测试数据纪律**：M1–M2 一律使用**副本**（`歌单样例/sync-v1.json`、`playlists.db` 的导出副本），**绝不拿用户真实云端文件做实验**；首次接真实数据前先做完整备份 + 导出。

## 7.6 成功指标、运维成本与退役判据（评审 I9）

| 维度 | 指标 / 判据 |
|---|---|
| 产品成功 | 连续 14 天无数据丢失报告；自动同步成功率 ≥ 99%；用户"需要我决定的事"平均每周 ≤ 1 次 |
| 运维成本 | 每周人工干预 ≤ 10 分钟；磁盘/内存占用有上限；升级不影响同步 |
| 复盘 | 每次真实事故 → 一条常驻回归用例（已在 §7.4）+ 状态页一条时间线记录 |
| **退役判据** | ① 客户端本身内置了跨端同步（如栖弦/澜音官方上线同步）；② 连续 3 个月零使用；③ 维护成本 > 收益。满足任一 ⇒ 导出 canonical JSON 交给用户，保留只读归档（D14 可逆） |
| 用户侧交付物 | 接入指南（图文，含"会发生什么/等多久/怎么算成功"，评审 M6/N7）+ 状态页 + 错误码→用户语言映射 + 常见问题（换机、重装、误删） |
