# 03 · 总体架构

## 3.1 定位与边界

**是什么**：一个自托管的同步枢纽。它对外**表现得像一个 WebDAV 服务器**，对内维护一份**统一歌单模型**与**每个客户端的基线**，在写入时完成"翻译 → 合并 → 落库 → 渲染回各格式"。

**不是什么**：不是播放器、不是音乐源、不是 AList 的替代品、不修改任何客户端代码、不要求用户安装插件。

## 3.2 分层与职责

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 客户端层（不改代码）                                                 │
│  栖弦(Android)   LX Music(桌面)   澜音+插件(可选)   未来任意 WebDAV 客户端│
└───────────────┬──────────────────────────────────────────────────────┘
                │  HTTPS + HTTP Basic（一个公共 URL + 账号密码）
┌───────────────▼──────────────────────────────────────────────────────┐
│ ① 接入层 Access                                                      │
│   WebDAV 门面（OPTIONS/PROPFIND/GET/PUT/MKCOL/DELETE/MOVE/COPY/HEAD） │
│   认证与空间解析（账号→成员表/角色→当前空间）· 邀请码 · 限流 · gzip · ETag · 错误码 │
├──────────────────────────────────────────────────────────────────────┤
│ ② 方言层 Dialect                                                     │
│   路由匹配 → 内容指纹探测 → 适配器 registry → 未知方言隔离容器        │
├──────────────────────────────────────────────────────────────────────┤
│ ③ 领域层 Domain                                                      │
│   canonical-v1 模型 · 合并引擎（基线差分/墓碑/删除优先/安全阀）       │
│   映射表（歌单身份）· 曲目身份（source+songId）· 审计与回滚           │
├──────────────────────────────────────────────────────────────────────┤
│ ④ 存储层 Storage                                                     │
│   SQLite：spaces / clients / baselines / playlists / tracks /        │
│           tombstones / journal / dialect_unknown                     │
│   可选：把用户数据目录落在 AList 存储上（可见、可迁移）               │
└───────────────┬──────────────────────────────────────────────────────┘
                │（可选）复用 AList 的账号/目录/权限
┌───────────────▼──────────────────────────────────────────────────────┐
│ AList（本机已有）：多用户 · 角色/路径权限 · Webdav read/manage · 存储 │
└──────────────────────────────────────────────────────────────────────┘
```

| 组件 | 单一职责 | 关键约束 |
|---|---|---|
| WebDAV 门面 | 讲协议、讲认证、讲限流；不理解歌单 | 必须通过各客户端真机兼容测试 |
| 方言层 | 判断"这是谁的数据"，调用对应适配器 | 识别不确定时**宁可隔离**，不可猜 |
| 合并引擎 | 唯一负责"该留什么、该删什么" | 纯函数式：同样输入必得同样输出 |
| 存储层 | 事务、基线、墓碑、历史；可备份可回滚 | 写失败绝不推进基线 |

## 3.3 部署形态

| 形态 | 客户端指向 | 优点 | 代价 | 采用 |
|---|---|---|---|---|
| **A · 门面**（推荐终点） | 枢纽 URL | 真双向 + 删除传播 + 全平台互通；未知方言可控 | 需要运行服务；WebDAV 兼容层要完整 | ✅ 目标形态 |
| **B · 守护进程** | 仍是 AList | 用户零改动、URL 不变；实现量最小 | 写-写竞争（AList 忽略 `If-Match`），靠"每端一个文件 + 只增不删 + 抖动重试"压低到"最多多同步一轮" | ✅ 作为 M0.5 验证与兜底 |
| **C · 与 AList 并存** | 两者各自 URL | AList 继续服务其它用途；互不干扰 | 需明确路径规划 | ✅ 部署约定 |

**路径规划（形态 C）**：AList 保留 `/dav/*`（现状 `https://yechoy.cn/dav/music`）；枢纽使用**独立路径或独立端口**，例如 `https://yechoy.cn/sync/`（反代另一端口）或 `https://sync.yechoy.cn/`。`/dav` 只是 AList 自己的路由前缀，**不是 WebDAV 协议要求**。

## 3.4 接入模型：一个 URL + 账号密码

**地址是共用入口，账号密码才是身份。**

| 方案 | 账号来源 | 优点 | 代价 |
|---|---|---|---|
| **甲 · 借 AList（推荐）** | AList 用户（用户已有一套） | 零注册页、零密码库；改密/停用/踢设备/路径限制全在 AList 生效；数据目录落在 AList 里可审计 | 与 AList 耦合（AList 不可用则无法登录）；需防"密码错误锁定服务器 IP" |
| **乙 · 自管账号** | 枢纽自己的用户表 | 与 AList 解耦；可做共享空间、只读凭据等自定义模型 | 要自己写注册/改密/吊销/配额；用户多记一套账号 |

**默认走甲**（决策 D13），乙作为可选开关。两方案对客户端完全一样：地址 + 用户名 + 密码。

### 3.4.1 认证流程（甲）

```text
客户端 ──Basic(user,pass)──► 门面
  1) 本地限流检查：同一账号/IP 连续失败 ≥5 次 → 直接 401（不转发，保护服务器 IP）
  2) 命中凭据缓存(5–10 分钟) → 放行
  3) 未命中 → 向 AList 校验（WebDAV/API，用专用校验账号或该用户凭据）
     200 → 缓存 (user → 空间, 路径权限, TTL)；401 → 计入失败计数
  4) 解析空间：space = user；得到该用户在 AList 的路径根与读写权限
  5) 进入 WebDAV 门面处理
```

**必须防的坑**：AList **连续 6 次密码错误封禁该 IP 30 分钟**（[用户文档](https://alistgo.com/zh/guide/advanced/user.html#tips)）。枢纽代表全体用户访问 AList，故第 1 步的本地限流是**安全必需品**，不是优化。

## 3.5 请求时序

### 3.5.1 首次接入（只增不删）

> **结论（源码已判定；真机复核保留为 M0.5 项）**：栖弦**先 GET 后 PUT**——`webdav_client.dart:45-48`（MKCOL → GET）、`webdav_sync_controller.dart:259-296`（`remote == null` ⇒ `write(local, createOnly: true)` 以本地为准；否则 section 级 LWW，远端胜就 `applyFromSync` 按远端**整体重建、缺席即删除**）。因此对**无基线客户端**的 GET **必须返回 `404`**，逼它走"远端不存在 ⇒ 以本地为准 ⇒ PUT"这条路；返回空间全量视图会让它先把这台设备自己的歌单清一次。
>
> **配套规则（评审 F1/A3）**：枢纽是空间唯一写者，**条件写头不构成失败**——`If-None-Match: *`（`webdav_client.dart:84`）与 `If-Match` 不符都**不返回 `412`**，一律按基线合并后返回 `200` + 新 ETag。若回 412，栖弦会整轮重跑（`webdav_sync_controller.dart:290-292`），首次接入时表现为**永久卡在"云端数据已被其他设备更新"**，新设备永远进不来。

```text
客户端 PUT /sync/space/<path>  {它自己的格式}
   → 指纹识别 → 适配器 parse → canonical
   → 该 client_key 无 base_submitted ⇒ 视作"全部新增"
   → 并入空间 canonical（不删除任何东西）
   → 建立 base_submitted / base_served = 本次交付的视图
   → 200 + 新 ETag
```

### 3.5.2 常规同步（客户端写入后）

```text
客户端 PUT {本地视图}
   → parse → C_new
   → base_served = 枢纽上次真正交付给它的视图（+ served_revision）
   → 差分：added = C_new − base_served；removed = base_served − C_new   （I2′：绝不用"它上次提交的视图"做差集）
   → 若 space.revision ≠ base_served.served_revision ⇒ 本次禁止产生删除（只并集 + 记候选）
   → 自动删除还需**正向归因**（评审 A1）：适配器往返无损 + `C_new ⊂ base_served` 严格子集 + 提交者身份可信；缺任一条 ⇒ 只记候选、不删（待确认队列）
   → 把 added/removed 应用到空间 canonical（三路合并）
   → 墓碑记录删除；安全阀：单次删除 > 阈值 ⇒ 可信端直接生效 / 不可信端既不生效也不出卡（**默认不再挂起确认**，D27）；`policy.confirm_delete=True` 时回到"挂起该批删除、新增照常应用"
   → `base_submitted = C_new`；`base_served` **不在这里推进**（PUT 的响应体不算交付，评审 F3）
   → 200 + 新 ETag（**不因为挂起而整批拒绝**，见 docs/05 §5.3.5）
```

### 3.5.3 读取（其它客户端取合并结果）

```text
客户端 GET
   → canonical(空间) + 该客户端已删除墓碑 → 渲染成该客户端格式
   → section 级 `modifiedAt` = `max(空间内容最后一次真变的服务端 UTC 时刻,
     该客户端上次交付的 modifiedAt + 1s)`，**仅当"相对该客户端上次交付内容确有变化"时才推进**；
     内容不变则字节完全相同。**必须是真实墙钟量级的值**（栖弦只比墙钟大小，
     `sync_models.dart:120-127`；给序号/过旧值 ⇒ 本地永远胜、别端新增永不落地，评审 F2）
   → **不返回 304**：栖弦只接受 2xx（`webdav_client.dart:69/91`），304 会被它报成
     "WebDAV 请求失败（HTTP 304）"。内容未变时返回 200 + 相同正文 + 相同 ETag
   → **只有 GET 的 200 交付才推进 base_served**（I1 / 评审 F3）
```

### 3.5.4 两端并发写

```text
A 端 PUT 与 B 端 PUT 几乎同时
   → 两次都基于各自 base 做差分（各自只声明"我加了什么/我删了什么"）
   → 合并引擎串行化执行（单写者事务）
   → 结果 = 两方新增并集 + 两方删除生效（同一首歌一加一删 ⇒ 删除优先，D7）
   → 两侧下一次 GET 都得到同一份合并结果
```

## 3.6 空间、隔离与配额

| 概念 | 定义 |
|---|---|
| 空间 space | 一份歌单集合的容器。**账号 ↔ 空间是多对多成员关系**（config v3，见 D24 / docs/12）：`members` 表记录每个账号在每个空间的角色 **owner / editor / viewer**，账号另有一个"**当前空间指针**"（同一时刻只生效一个空间）。加入他人空间必须持有效**邀请码**；普通账号可自助创建属于自己的空间（受配额，默认 ≤3）。歌单在成员间真合并、双向、删除自动生效；**opaque（主题/音源/本地音乐）按 `client_key` 分桶存储与渲染，不跨设备交付**（D23）。viewer 只读，同步 GET 走引擎纯只读 `peek_view`、PUT/网页改删一律 403。**空间名即 `space_id`**，也是 pkl 文件名（`data/spaces/space__<id>.pkl`）与 WebDAV 地址语义，v3 不改变 pkl 路径与存储结构 |
| 客户端 client | 空间内的一个同步参与者，`client_key = (账号/空间, 方言, 设备标识)`。设备标识优先取 `X-Hub-Device` 请求头，其次取 URL 设备段 `/d/{device}/...`，都没有则退化为 `default`（2026-10-06 多设备改造已实现；`api.client_identity` 归一化，限 `[A-Za-z0-9_-]{1,32}`，非法 400）。栖弦/澜音默认仍只填一个 URL（D10）；**同地址两台设备不额外配置时共享 `default` 身份**（残差保护见 D10 / docs/05 §5.1 R1）。不再用 `User-Agent 家族` 参与身份（只能粗分、分不开同 App 两台设备） |
| 隐藏关系 | 用户之间不共享数据、不共享日志；跨空间不合并 |
| 配额 | 每空间文档数/总字节上限；超限 `507`；单请求体上限与客户端一致 |
| 生命周期 | 改密/吊销立即生效（数据保留）；删除空间需二次确认 + 可导出备份 |

## 3.7 存储模型（逻辑）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `spaces` | id(=name=space_id), kind(personal/shared), created_by, created_at | 空间；id 即空间名与 pkl 文件名，v3 不改变物理路径 |
| `accounts` | username, password(pbkdf2), **space（当前空间指针）**, global_role(admin/user), enabled | 账号；同一时刻只生效 `space` 指向的那一个空间（D24） |
| `members` | **space_id, account, role(owner/editor/viewer), joined_at, invited_by** | **v3 多对多成员表**：一个账号可加入多个空间、一个空间可有多个成员；每非孤儿空间 ≥1 owner |
| `invites` | **code, space_id, role(editor/viewer), created_by, expires_at, max_uses, uses, note, disabled** | **v3 邀请码**：加入他人空间/自助注册的唯一凭证；失效四态（不存在/撤销/过期/用尽） |
| `clients` | id, space_id, client_key, device_id, dialect_id, **identity_verified**（是否已越过删除点：见 I7/D21）, first_seen, last_seen, **retired_at**（>180 天未出现 ⇒ `retired`，排除在墓碑 GC 条件外）, ua | 参与者 |
| `baselines` | client_id, **served_revision**, **element_keys + view_hash（交付基线，只存键清单与哈希，不存整份视图）**, submitted_revision, submitted_hash | **每客户端基线**（核心）；整份视图按 `canonical_revision` 共享物化、按需重建（评审 I4） |
| `playlists` | id, space_id, name, cover, attrs_json, created_at, updated_at | 歌单 |
| `tracks` | id, playlist_id, source, song_id, position, fields_json, added_at | 曲目（`(space,source,song_id)` 去重池） |
| `tombstones` | space_id, kind(playlist/track), target_key, deleted_at, origin_client, **created_at_revision, ack_mask** | 删除墓碑；**GC 只看 `ack_mask`（删除时已注册的客户端是否都已在提交内容中确认应用该删除），无时间 TTL**（D21，评审 C 节）；**确认一律来自提交内容**（提交视图里不再携带该条目）——GET/交付不算确认：栖弦是"整段覆盖"端点，拉取后本地可能仍保留副本，交付即 ack 会让墓碑被提前 GC、残留回推复活已确认删除（第三轮删除回环修复，复检 S11/S15） |
| `journal` | seq, space_id, client_id, action, delta_json, at | 审计/回放（可导出、可回滚） |
| `dialect_unknown` | client_id, path, fingerprint, sample_head, first_seen | 未知方言隔离容器 |

## 3.8 可观测性（"出问题别让我猜"）

| 视图 | 内容 |
|---|---|
| **用户状态页（本阶段必备，评审 UX S4）** | 同一账号密码登录的只读页，首屏四问：**上次同步成功是什么时候 / 每台设备上次做了什么 / 有没有需要我决定的事 / 我的数据存在哪**；并承载"待确认删除、隔离、新设备身份、待清理清单"四类确认卡 |
| 每客户端状态 | 上次同步时间、方向、增量条数、当前是否隔离、错误原因 |
| 同步日志 | 每次 PUT/GET 的 diff（added/removed 的歌名，人类可读） |
| 发现事件 | 未知方言出现（路径、UA、指纹、样例）→ 提示"补适配器即可接入" |
| 健康检查 | 进程存活、DB 可写、磁盘余量、最近 N 次失败率 |
| 冲突报告 | 安全阀触发、删除比例异常、并发写重试次数 |
| 告警送达渠道 | 状态页横幅为**必需**；邮件/webhook 可选（评审 N7：自托管单人场景下"告警"可能无人接收） |

## 3.9 性能预算

| 指标 | 目标 | 手段 |
|---|---|---|
| 单文档大小 | 硬上限 1 MiB；**工程目标 ≤100 KB**（AList 历史截断点约 108 KB，须留余量） | 曲目池去重、字段自净、ext 限额 64 KiB；**绝不裁剪曲目**（裁剪=对客户端静默丢歌） |
| 传输 | gzip 5–8×（237 KB → ≈35 KB）；**不使用 304**，内容未变返回 `200` + 相同正文与 ETag | 门面统一压缩；条件请求只用于写入（`If-Match`/`If-None-Match`） |
| 合并 | `O(n+m)`，n/m 为两侧条目数；单空间千级歌单/万级曲目可接受 | 哈希索引 + 集合运算 |
| 延迟 | 本地门面单次同步 < 300 ms（不含网络） | 单写者事务 + 预渲染缓存 |
| 并发 | 单空间串行写、跨空间并行；重试用抖动退避 | 写锁粒度 = 空间 |
