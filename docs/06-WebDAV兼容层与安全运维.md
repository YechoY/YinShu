# 06 · WebDAV 兼容层、安全与运维

## 6.1 WebDAV 兼容层清单（"任意客户端都能接"的底线）

门面必须实现的标准子集。**任何一项缺失都可能导致某个客户端直接报"同步失败"**。

| 方法 / 特性 | 要求 | 为什么需要 |
|---|---|---|
| `OPTIONS` | `DAV: 1`，`Allow: OPTIONS, HEAD, GET, PUT, PROPFIND, MKCOL`（`DELETE`/`COPY` 本阶段 `501`，故不列入 `Allow`；`MOVE` 若实现再加入） | 客户端探测能力 |
| `PROPFIND` | `Depth: 0/1`；标准 `multistatus`；属性 ≥ `resourcetype, getcontentlength, getlastmodified, getetag, displayname, creationdate`；支持 `<allprop>` 与具名属性 | 客户端常先列目录判断"文件是否存在" |
| `HEAD` / `GET` | 正确 `Content-Length`、`Content-Type: application/json`、`ETag`、`Last-Modified`；**不使用 `304`**：内容未变也返回 `200` + 相同正文与相同 `ETag` | 取合并结果。栖弦 `validateStatus: status < 600` 但 `read()` 对 `<200 或 ≥300` 抛异常（`webdav_client.dart:68-69`）⇒ **304 会被它当成失败**，条件读优化对它有害；省流量靠 gzip |
| `PUT` | 支持 `If-None-Match: *`（首次创建）与 `If-Match`（条件写，尽力而为）；返回新 `ETag`；父目录不存在时按真机行为选择"自动创建"或 `409` | 写回；栖弦首次同步用 `If-None-Match: *` |
| `MKCOL` | 新建 `201`；已存在 `405`；父目录缺失时按真机行为"自动补齐父目录"或 `409`（**M0.5 用栖弦实测确定**） | 栖弦启动会调用（`webdav_client.dart:53`），它接受 `200/201/204/405`（`:56`）；**`409` 会让它报"WebDAV 目录无法创建"** |
| `DELETE` | **本阶段不实现，返回 `501`**（客户端"重置同步"用覆盖写即可；实现它等于给"整份删除"开一条无归因的口子，评审 F9） | 兼容 |
| `MOVE` / `COPY` | 可选：`MOVE` 供插件原子写（临时文件 + `MOVE`）使用，支持 `Destination`/`Overwrite`；未实现的动作一律 `501` | 插件原子写、部分客户端重置流程 |
| `LOCK` / `UNLOCK` | 先返回 `501` | 少数客户端依赖加锁；真机遇到再实现伪锁（返回随机 token，`Timeout` 头） |
| 压缩 | 响应支持 `gzip`；请求接受 `gzip`/`identity` | 性能（237 KB → ≈35 KB） |
| 认证 | `401` + `WWW-Authenticate: Basic realm="…"` | 客户端凭据输入 |
| 错误码 | **统一语义表**：`400` 坏请求 · `401` 未认证（**匿名探测也用 401，但不计入失败限流**）· `403` 无权限 · `404` 不存在 · `405` MKCOL 已存在 · `409` 父目录/集合冲突（**不用于安全阀**——挂起的删除按 `200` 正常交付 + 待确认卡，见 `docs/05` §5.3.5） · `412` 条件写失败（**我方不主动返回**，见 §6.1 条件写规则） · `413` 太大 · `423` 锁定 · `429` 限流（带 `Retry-After`；**绝不用 401 表达限流**，否则正确密码的用户会以为密码错了）· `501` LOCK 未实现 · `507` 空间已满 | 客户端依据状态码决定重试/放弃。**栖弦只把它翻译成 4 类文案**（`webdav_client.dart:123-130`：401/403→密码权限、409→目录无法创建、412→云端已被其他设备更新、其它→"请求失败（HTTP N）"）⇒ 真正给用户看的解释必须落在状态页（`docs/10` A6） |
| 路径语义 | 目录以 `/` 结尾；大小写敏感；URL 编码按 RFC 3986（中文歌单名/文件名要能通过） | 兼容 |
| User-Agent | **原样记录**（用于 `client_key` 与方言识别） | 身份区分 |

**已知客户端怪癖登记**

| 客户端 | 行为 | 对策 |
|---|---|---|
| 栖弦 | 启动发 `MKCOL`；`If-None-Match: *` 建文件；读取 `ETag`；`If-Match` 412 重试（在 AList 上从不触发）；**只接受 2xx**；`_sameSnapshotData` 相等时不写回 | 门面必须正确返回 ETag 与 `412`；`MKCOL` 已存在返回 `405`、新建 `201`；**绝不对它返回 `304`**；相等即不写 = 该端自己的删除可能不传播（见 `docs/05` §5.6 已知限制） |
| 澜音插件 | 写回后回读自校验；用临时文件 + `MOVE` 原子写；`PROPFIND`/`DELETE` 可用 | 支持 `MOVE` 覆盖语义与写后立即可读 |
| LX Music | **待研究**（M4 前取证：路径、格式、方法、条件写） | 见 `08-风险与开放问题.md` |

## 6.2 认证、凭据与隔离

| 项 | 设计 |
|---|---|
| 认证方式 | HTTP Basic over HTTPS（与 AList 习惯一致） |
| 身份 | 用户名 = 空间；密码只用于认证，不用于派生密钥 |
| 密码存储 | 乙方案：只存哈希（scrypt/argon2；绝不明文）；甲方案：不落库，向 AList 校验 |
| **失败锁定防护** | 失败计数**按 IP（不按账号）**，同 IP 连续失败 ≥ 5 次 ⇒ 本地直接拒绝并返回 `429` + `Retry-After`（**不转发给 AList**），退避 30 分钟。理由：① AList 连续 6 次封 IP 30 分钟，而枢纽代表全体用户访问 AList；② 按账号计数可被"枚举用户名"用来锁死合法用户（评审 I5） |
| 独立同步密码（建议随 M3 做） | 允许为同步单独设一个密码，与 AList 登录密码解耦；改这个密码不影响用户登录 AList，也避免"全家共用一个密码时一人输错锁全家"（评审 M2） |
| 凭据缓存 | 校验成功缓存 5–10 分钟（`user → space, permissions`），降低 AList 压力 |
| 推荐做法 | 用一个**专用 AList 账号**或 API token 做校验，隔离"某个用户输错密码"的风险 |
| 传输安全 | 强制 HTTPS；拒绝明文 HTTP 上的 Basic（或重定向到 HTTPS） |
| 撤销 | 改密/停用/吊销在 AList 侧一次生效；本地校验缓存 TTL **60–120 秒**（原"5–10 分钟"与"改密立即生效"矛盾，评审 I5），并提供"立即失效"旁路（下次请求强制回源校验） |
| 隔离 | 空间之间物理隔离（不同 `space_id`）；日志按空间脱敏；不存在跨空间查询接口 |
| 隐私 | 日志默认不记密码/token；`Authorization` 头永不落盘 |

## 6.3 配额与限流

| 项 | 默认 | 说明 |
|---|---|---|
| 单空间存储 | 32 MiB（可配） | 超限 `507` |
| 单请求体 | ≤ 4 MiB | 与澜音插件限制对齐 |
| 单文档 | < 1 MiB（目标 100 KB 量级） | 规避历史截断风险 |
| 写入频率 | 单客户端 ≥ 5 s 间隔（抖动允许） | 防抖与风暴保护 |
| 并发写 | 单空间串行 | 单写者事务 |
| 每账号客户端数 | ≤ 20 | 防"新身份"爆炸 |
| 未知方言空间 | 每空间 ≥ 1 个 | 记录发现事件 |

> **v3 空间与成员体系（D24）上公网前的强制加固**（本机/可信局域网默认不启用，见 docs/12 §8、docs/08 Q18）：
> 1. **默认口令**：无 config.json 时的 `admin/admin123` 必须在首登时强制修改；
> 2. **认证与加入限流**：对 Basic 登录、`POST /api/join`、`POST /api/register` 做按 IP/账号的失败计数 + 指数退避 + 临时锁定，否则邀请码（8 位字符集）可被枚举、口令可被爆破；
> 3. **公网关闭自助注册**：把 `policy.allow_self_register` 置为 `false`，或仅在需要邀请家人时临时打开、用完即关；邀请码设置短有效期、`max_uses=1`；
> 4. 全程 HTTPS（反代或隧道），避免 Basic 凭据与邀请码明文传输；
> 5. 配置与 `data/spaces` 定时异地备份、`_audit.jsonl` 日志轮转。
> 上述限流/首登改密**本期尚未实现**，当前版本定位为本机/家庭可信网络使用。

## 6.4 备份、恢复与回滚

| 能力 | 设计 |
|---|---|
| 自动备份 | SQLite 定时快照（如每 6 小时 + 每次大变更前），保留 N 份 |
| 导出 | 一键导出 `canonical-v1` JSON（人类可读）+ **各客户端原格式**文件（D14：迁移可逆） |
| 回滚 | 按 `journal` 重放到任意 `revision`；或"恢复到时间点" |
| 演练 | 上线前做一次"删库/改坏数据 → 恢复"演练，并记录耗时 |
| 冷备 | 用户目录若落在 AList 上，则另有 AList 侧副本 |

## 6.5 监控与运维

| 项 | 内容 |
|---|---|
| 健康检查 | `GET /healthz`：进程、DB 可写、磁盘余量、最近失败率 |
| 指标 | 每客户端同步次数/成功率/增量条数、合并耗时、安全阀触发次数、未知方言数 |
| 日志 | 结构化（JSON 行）：时间、空间、客户端、动作、diff 摘要、结果、耗时 |
| 告警 | 连续失败、安全阀触发（挂起删除）、磁盘 < 10%、未知方言出现、AList 校验连续失败 |
| 告警送达渠道 | **状态页横幅为必需**（自托管单人场景没有值班人，邮件/webhook 常没人看，评审 N7）；邮件/webhook/`ntfy` 为可选 |
| **错误码 → 用户语言映射（必备交付物，评审 I7/UX S1）** | 例如 `412` → "另一台设备刚刚更新过，本轮已重新同步，请再看一眼"；**挂起的删除不是错误码** → `200` + 状态页待确认卡"有一批删除量异常，已暂缓，请确认"；`507` → "同步空间已满，请清理或扩容"；`409` → "目录/集合冲突，请检查路径"（**不是**安全阀）。**落点是状态页，不是客户端弹窗**（客户端的文案不受我们控制） |
| 升级 | 版本化 schema 迁移；**先备份后迁移**；支持回退上一个版本 |
| 部署 | 本机进程 + 反向代理（路径 `/sync/` 或子域名）；开机自启；隧道复用现状 |

## 6.6 失败模式与处置（"不丢数据"底线）

| 失败 | 用户感知 | 数据影响 | 处置 |
|---|---|---|---|
| 枢纽进程挂了 | 客户端同步失败（可重试） | **无**（客户端本地数据仍在） | 自启 + 健康检查；不写坏数据 |
| 隧道/网络断了 | 同上 | 无 | 客户端稍后重试 |
| AList 不可用（甲方案） | 登录失败 | 无 | 本地凭据缓存可短期兜底；提示"认证服务不可用" |
| 客户端文件被截断/坏 JSON | 该端同步失败并提示 | 无（落库前拒绝） | 拒绝 + 保留原文件 + 记录样例 |
| 合并中途崩溃 | 该请求失败 | 无（事务回滚，基线未推进） | 重放幂等 |
| 磁盘满 | 写入失败 | 无 | `507` + 告警 + 停止接受写 |
| 客户端 bug 大量删歌 | 触发安全阀：**挂起该批删除、其余照常应用**，返回 `200` + 状态页待确认卡（**不是 `409`**，否则栖弦永久卡在"目录无法创建"） | **无** | 要求确认；可用 journal 回放恢复 |
| 未知格式客户端接入 | 它能正常读写自己的数据，但不参与合并 | 无 | 隔离 + 记录发现事件 + **通知用户正在识别** + 补适配器后**经用户确认**并入 |
| 误删后想找回 | — | 可恢复 | journal 回放 / 备份 / 导出文件 |

**应急处置速查**：

1. 先**停写**（拒绝新 PUT），保现场；
2. `journal` + 备份确认影响范围；
3. 导出受影响空间的 canonical JSON 与各客户端原格式，人工核对；
4. 回滚到目标 revision，再恢复写入；
5. 事后补一条验收用例（每个事故都应变成一条测试）。
