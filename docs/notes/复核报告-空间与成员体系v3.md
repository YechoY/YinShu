## §2 必修项（P0，各 1–5 行代码）

1. **`/api/state` 缺读鉴权** — `src/hub/api.py:1369-1376`
   - 现状：`:1371-1373` 只校验 Basic 身份，随后直接 `:1374 space = _users[user]["space"]`、`:1375 rt = _hub.get(space)`，**全区间无 `_require_role(user, space, "read")`**；`/api/state` 会返回该空间歌单内容（`:1385-1400`）。
   - 风险：不变量①（账号的 space 必须是其成员空间）是唯一防线；一旦该字段被改坏/写错，账号即可读到非成员空间的内容（读侧 `_sync_get:1700` 是有门的，`/api/state` 破了口子）。
   - 修法：在 `:1374` 之后插入
     ```python
     deny = _require_role(user, space, "read")
     if deny is not None:
         return deny
     ```
   - 验收：新增用例——把某账号 `space` 直接改成它不是成员的空间（直接改 `_users`）→ `GET /api/state` 返回 403。

2. **邀请码可被「已在空间内的成员」重复消耗 + viewer 可列码** — `src/hub/api.py:1101-1104`、`:1034-1042`
   - 现状：`POST /api/join`（`:1087`）对**已经在该空间的成员**也执行 `uses += 1`（`:1104`）⇒ owner 发一张一次性码，成员误点一次就把码用尽，外部的人再也进不来。
   - 现状二：`GET /api/invites`（`:1027-1042`）只按 `created_by` 过滤，未按 `policy.member_invite` 拒 viewer（而 `_invite_manager:974-981` 是给了 editor/viewer 条件的）⇒ 只读成员能列出码。
   - 修法：join 时若 `user in _members[space]` 直接返回 200「已在该空间」且不消耗；`GET /api/invites` 对非 owner/editor 返回 403。
   - 验收：成员用码 join → `uses` 不变；viewer `GET /api/invites` → 403。

## §3 建议修（P1）

3. **建号不校验空间名 → 静默新建空间** — `src/hub/api.py:545`（`space = str(body.get("space") or name).strip() or name`）
   - 与「禁止静默新建空间」的约定矛盾（对照 `:746-752` 的 404 守护）；管理员把 `main` 打成 `maim` 会凭空多一个共享空间。
   - 修法：`if space != name and not _space_exists(space): return 404 「空间 … 不存在」`（个人空间同名隐含允许）。
4. **审计「最近 30 条」过滤次序** — `src/hub/api.py:1485`
   - 先取全库尾部 30 条再按 space 过滤 ⇒ 本空间可能不足 30 条；且 `space` 为空的全局记录（`:801-802 space.quota`）泄漏到每个空间。
   - 修法：先按 space 过滤，再取尾部 30。
5. **改名不同步 `members[*][*]["invited_by"]`** — `src/hub/api.py:1201-1211`
   - 改名已维护 members 键、`spaces.created_by`、invites 的 `created_by`/`invited_by`，但漏了成员表里的 `invited_by`（`/api/spaces/{name}/members:908` 会暴露这个过期字段）。
6. **不变量①无运行时断言/告警** — `src/hub/api.py:132-172`
   - 建议迁移时对「account.space 不是其成员空间」写一条 `_audit` 告警（不改行为）。

### §4.1 `peek_view` 实现复核（已逐行读过 `src/engine/engine.py:313-327`）

- 做的事：造一个**不注册进 `self.clients`** 的临时 `Client(client_id="__peek__:<dialect>")`，调既有的 `render_for(tmp)` 渲染当前权威视图；stamp 取 `max(content_changed_at, order_changed_at)`（确定性）。
- **没做的事**（与 `deliver`（`:293-311`）逐条对比）：不注册客户端、不推进 `base_served`/`base_submitted`、不 ack 墓碑（`deliver:305-306`）、不调 `_gc_tombstones()`（`deliver:307`）、不写 journal（`deliver:309-310`）、不改 `revision`/stamp。⇒ **纯读，不影响 R1 / I2′ / GC / 安全阀任何不变量**。
- 唯一实质缺口：**引擎自己的用例 0 覆盖**——全仓 grep `peek_view` 只命中 `src/hub/api.py:1711` 与 docs，`tests/engine/**` 无引用，目前只靠 `tests/hub/test_spaces_http.py` 的 viewer 用例间接保护。
- 建议补 1 条引擎级用例（`tests/engine/`）：调用 `peek_view` 前后对 `revision`、`stamp`、`dict(engine.clients)`、`{k: set(t.acked) for ...}` 做快照对比，断言**逐字节不变**；若同意追认，规格里同时写清「只读」的判据＝不改 revision/stamp、不注册客户端、不 ack、不 GC、不写 journal。
