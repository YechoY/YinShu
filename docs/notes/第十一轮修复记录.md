**结论**：洛雪确实把它删掉并整份提交了，枢纽**明确识别出了这次缺席**（记在 `never_owned` 里），却按 R1 规则拒绝判删 —— 不是"没收到"，是"故意不删"。

## 2. 真因

R1（《多设备同步改造方案.md》§3.2，2026-10-06）规定删除判据：

```text
owned = base_served ∩ base_submitted     # "这台设备自己提交过"的条目
```

这条修正的初衷是 M1 事故：栖弦是"先 GET 再按 section 级 LWW 决定写不写回"的整段覆盖客户端，A 机 GET 后可能保留自己的旧段回写，把 B 机刚加的内容（在交付视图里、但 A 从未提交过）判成"A 的删除"。

但洛雪（`lx-lxwalnut-music-mobile/src/core/sync/webdavSync.ts:438-489`）的同步手续是：

```text
hasRemoteUpdate = remoteTimestamp > localTimestamp
hasRemoteUpdate → mergedData = remoteData.data，本地操作队列 replay
                → overwriteListFull(mergedData)        # 本地整份被远端覆盖
                → 仅当 hasLocalChanges 才 uploadLists(mergedData)
```

⇒ **纯拉取时它一次都不上报**。"枢纽给过、自己没提交过"在洛雪这里不是"没采纳"，而是"当时还没有它后来删了它"。R1 要保护的"M1 危险面"在洛雪身上根本不存在（它不会保留自己的旧段），而 R1 的副作用（删除永久静默无效）正好落在这里。

## 3. 修复

按**方言能力**放松，不改 R1 本身；三道约束一道不减。

`src/engine/engine.py`：

```python
class Client:
    full_view_submit: bool = False           # 该方言每次提交都是"整份视图"
    round_trip_sources: Optional[frozenset] = None   # 能原样往返回来的音源前缀

# merge() 内
full_view = bool(client.full_view_submit and client.identity_verified
                 and not client.retired and client.can_delete)
owned_pl = set(base_keys) if full_view else base_keys & set(sub_view.keys())
...
if full_view and client.round_trip_sources is not None:
    owned_t[pl] = {k for k in base if k.split(":", 1)[0] in client.round_trip_sources}
else:
    sub = set(sub_view[pl].get("tracks", ())) if pl in sub_view else set()
    owned_t[pl] = base & sub
```

- 歌单级放松同样成立：整份视图里缺席的歌单 = 删掉的歌单；
- `round_trip_sources` 只放行"该方言解析后仍能原样返回的音源"（洛雪 = `wy/tx/kw/kg/mg`）：解析会把白名单外的曲目丢进 `opaque["tracks"]`，那些曲目在提交里天然缺席，**不能**当删除意图 —— 宁可不删，不可误删；
- **I2′ 并发闸门**照旧（交付之后别端写过 ⇒ 只记 `suspects`、不判删）；
- **安全阀**照旧（可信端直删 / 不可信端不生效不出卡）。

`src/hub/store.py`：`client_for()` 从 `DIALECT.capabilities` 透传两个新字段；`_repair_engine_fields()` 为旧 pkl 里的客户端补默认值。**坑**：dataclass 的类级默认值让 `hasattr(client, "full_view_submit")` 恒为真，必须查实例字典：

```python
if "full_view_submit" not in c.__dict__ or "round_trip_sources" not in c.__dict__:
    ...
```

`src/hub/adapters/lx.py`：

```python
"full_view_submit": True,
"round_trip_sources": tuple(sorted(_KNOWN_SOURCES)),
```

**栖弦 `full_view_submit=False`**（section 级 LWW 可能保留旧段，放松会误删别人加的歌）；**澜音插件 `False`**（本地删不掉，缺席可能只是导入失败）。两者继续走 `∩ base_submitted`。

## 8. 教训

1. **"能删本地"与"缺席即删除意图"是两件事**，取决于客户端**怎么把本地状态送上来**；能力表要问的不是"支不支持删除"，而是"每次提交是否都是完整视图"。
2. 同一个 `capabilities` 表要区分"客户端**声明**吃了什么"和"它**还能退回**什么"：解析丢弃的条目（洛雪的非白名单音源）不能参与删除判据 —— 放松前必须先划出"能原样往返"的集合。
3. **dataclass 的类级默认值会让 `hasattr` 恒为真**，给旧快照补字段必须查 `__dict__`；这个坑本项目中已出现两次（`confirm_restore`、本轮）。
4. 验证要**在这份现场数据的副本上**复演用户的操作序列（`verify_lx_delete_live.py`），而不是只跑合成的单测：真机序号（谁先 GET、谁在什么时刻提交）本身就是判据的一部分。
