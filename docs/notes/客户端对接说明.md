# 客户端对接说明（可直接转发给客户端开发者）

> 背景：我们自建了一个**服务端合并枢纽**（`playlist-sync-hub`，FastAPI）。澜音插件、栖弦、洛雪三个客户端都连它，各自上传自己格式的整份歌单文件，枢纽做**三路合并**后按各自格式返回。客户端不需要懂别人的格式。
>
> 这份文档说明**客户端需要怎么连**，以及**希望客户端配合做的几件事**。除特别注明外，枢纽侧的活我们来做，**客户端改动都很少**。

---

## 0. 通用接口契约（三个客户端都一样）

**认证**：HTTP Basic —— 用户名 = 枢纽账号，密码 = 账号密码。用户名决定"**空间**"（分享单位），客户端不需要知道空间名，地址里也不出现空间名。

**设备身份**：请客户端**自动上报**，不要让用户手拼地址。两种写法二选一，**推荐第一种**：

| 写法 | 例子 | 说明 |
|---|---|---|
| ✅ **请求头**（推荐） | `X-Hub-Device: <设备名>` | 用户只填枢纽根地址 `http://<枢纽>:8000`；设备名由客户端首次开启同步时生成并持久化 |
| 兜底：地址里带设备段 | `http://<枢纽>:8000/d/phone` | 仅当客户端无法加自定义请求头时使用；用户要手填，不推荐 |

- 设备名规则：`[A-Za-z0-9_-]{1,32}`，非法会被拒（400）。**头优先于路径段**，二选一，**不要同时用**。
- 设备名建议：首次开启同步时随机生成一个稳定短名（如 `cyshine-a1b2c3` / `lx-9f3k2p`）写进本地设置，之后每台设备固定用它；改名 = 新设备（安全，只会新增不会误删）。
- **同一账号 + 同一客户端 + 不报设备名 = 同一台设备**：两台机器共用一份同步基线，A 机器还没同步到的新歌在 B 机器提交时会被判成"删除"。所以**多设备必须各报一个设备名**。

**响应约定**

- `GET` 成功返回 **200 + 该客户端格式的完整文件**；**枢纽永不返回 304** —— 请按内容比较判断是否需要回写，不要依赖 `If-None-Match` 的 304 分支。
- `PUT` 成功返回 2xx；请求体就是客户端自己格式的整份文件。
- 枢纽会发 `ETag`，也接受 `If-Match` / `If-None-Match`，但**不会**用 304 回你。
- 没有远端数据时，可能返回 **404**、也可能返回 200 + 空视图 —— 两种都要按"远端为空"处理。
- 目录探测：`MKCOL`（目录路径返回 201，幂等）、`HEAD`、`OPTIONS`、**`PROPFIND`（返回最小合法 207 multistatus）** 都支持；**不需要真的建目录**。

## 1. 给栖弦（CyShineMusic / CyShineMusic-Y）开发者

### 1.1 现状

栖弦**今天就能连枢纽**：`lib/core/sync/webdav_client.dart:32-33` 的 `${baseUrl}/CyShineMusic/sync-v1.json` 正好对上枢纽的 `/CyShineMusic/sync-v1.json`。地址/账号可配，`sync-v1.json` 的外形不用改。

**两个问题**：① 多设备会被当成同一台设备（下一条解决）；② 删歌传不过去（1.3）。

### 1.2 需求一：自动上报设备名（一行）

在 `_request` 里加请求头（和 Basic 认证头同一处）：

```
X-Hub-Device: <设备名>
```

设备名首次开启同步时随机生成（如 `cyshine-a1b2c3`）并持久化到本地设置（建议新增 `webdav_sync_device_v1`），设置页可改；只允许 `[A-Za-z0-9_-]{1,32}`，非法就拒绝保存并给中文提示。**地址与路径拼接保持原样，用户不需要做任何事。** 两台设备各报一个名字，枢纽就会给它们各自独立基线，互不误删。

### 1.3 需求二：删除传播需要一处行为改动

枢纽的删除结果**目前可能被栖弦丢掉**，根因两条：

1. **section 级 LWW 用本机墙钟**：`sync_models.dart:120-127 newerSyncSection()` 比 `modifiedAt`（本地是设备墙钟毫秒）。枢纽交付的 `modifiedAt` 只保证"比自己上次交付大"，打不过设备墙钟 → 栖弦认为"本地更新"，丢弃远端并把自己那份推回去，**删除被撤销**。
2. **纯拉取不 ack**：`webdav_sync_controller.dart:286` 在"合并结果与远端相同"时直接 `return`，不 PUT。枢纽的墓碑确认只发生在合并里 → 墓碑只增不减。

**建议**：新增同步模式开关 `mirror`（默认，现状，用于自建网盘）/ `hub`（连枢纽）。`hub` 模式下：

- 不跑 `newerSyncSection`，**直接把远端快照当权威**（`_applyRemoteSections(local, remote.snapshot)`）；
- 然后把本地视图**整份 PUT 一次**（即使 `_sameSnapshotData` 为真也要 PUT），用于 ack 墓碑。

`sync-v1.json` 的外形**不用改**（枢纽把 `appearance` / `musicSources` 按客户端分桶原样保管，不跨设备下发）。

### 1.4 不要做的事

- 不要在地址里拼 `/d/xxx` 的**同时**又发 `X-Hub-Device`（头优先，会打架）；
- 不要把非 2xx 一律当致命错误：`404` 请当"远端还没有数据"（你现在的 `read()` 已经这么处理，保持即可）。

## 2. 给洛雪开发者

### 2.1 我们读了你的源码（`lx-lxwalnut-music-mobile`），先回答你可能会问的三件事

1. **地址与目录都能配置** ✅ —— `src/utils/webdav.ts:11-20` 读 `settings['sync.webdav.url']`，`src/core/sync/webdavSync.ts:56-72` 读 `settings['sync.webdav.path']`（默认 `/LX_Music/`）拼 `<path>/playlists.json`。所以用户只要把 base 换成枢纽根地址、目录名写 `lx-x` 即可，**不需要拼 `/d/`**。
2. **可以加自定义请求头** ✅ —— 你们用的 `webdav@5.8.0` 的 `WebDAVClientOptions` 就有 `headers?: Headers`（还有 `client.setHeaders()` 和每请求 `options.headers`）。所以设备身份可以自动上报。
3. **你们的同步语义对我们友好** ✅ —— `webdavSync.ts:438-508`：远端 `lastModified` 比本机水位（`sync.webdav.lastSyncTimeLists`）新时，以**远端为底** replay 本地操作队列（`src/core/sync/opQueue.ts` 记录的增删操作）后整份 PUT；没有本地改动就直接采纳远端并更新水位。所以枢纽的删除**能被洛雪接受**，不需要额外加"以远端为准"的模式。

### 2.2 想请你们配合的事

**唯一的硬需求（一处代码）**：**每个请求加 `X-Hub-Device: <设备名>`** —— 设备名首次开启同步时随机生成并持久化（如 `lx-9f3k2p`），设置页可改，规则 `[A-Za-z0-9_-]{1,32}`。就在 `src/utils/webdav.ts:20`：

```ts
client = createClient(url, { username, password, headers: { 'X-Hub-Device': deviceId } });
```

**不要**把设备名拼进地址。（仓库里没有现成的设备 id 工具，需要自己生成一个并持久化。）

**下面三条"保持现状"就行，我们这边已经对齐**：

2. **三个文件都走同一套地址**：`webdavSync.ts:62-72` 的 `playlists.json` / `settings.json` / `user_apis.json` 枢纽都收（后两个原样存、原样还）；如果你们以后改了路径规则，提前说一声。
3. **顶层 `playHistory` / `downloadTasks` 继续带着**：`hasLocalExtraDataChanges()`（`webdavSync.ts:173-180`）会把它们纳入"本地是否有改动"的判断，枢纽会**按客户端分桶原样还**，两者必须对得上，否则每次同步都会被判成"有本地改动"而反复上传。
4. **`version`、曲目 `id`、`interval` 保持现状**：`version` 是字符串 `"2"`、曲目 `id` 原样字符串（含 `545879713_E3426FF…` 这种没有 `kg_` 前缀的老格式）、`interval` 是 `mm:ss` —— 我们都原样回写，不改写、不重算。

### 2.3 枢纽会怎么对待你的文件（承诺）

- **只有 `data.userList`（用户自建歌单）参与合并**，回写仍是你的外形（`version:"2"` 字符串、epoch 毫秒 `lastModified`、`interval` 用 `mm:ss`）。
- `data.defaultList` / `loveList` / `tempList`（真机 722 / 232 / 301 首）、顶层 `playHistory` / `downloadTasks`、以及 `settings.json` / `user_apis.json`：**按客户端分桶原样保管、原样返回**，不合并、不跨设备 ⇒ **不会被别人清空，也不会被发送给别人**。
- 曲目 `id` **原样回写你给的字符串**；只有"别的客户端带进来的新歌"我们才会合成 `"<source>_<id>"`。
- 歌单附加键（`origin` / `source` / `sourceListId` / `locationUpdateTime`）原样透传；枢纽新建的歌单给 `origin="created"`、`locationUpdateTime=null`。
- 我们不写你不认识的键、不加额外的顶层键。

### 2.4 我们要在枢纽侧改的（你们不用管）

- **补 `PROPFIND`**：你们的 `ensureDirectoryExists()`（`src/utils/webdav.ts:43-60`）靠 `cli.exists()`（= `stat` = PROPFIND）判断目录，而 `webdav@5.8.0` 的 `exists()` 只把 **404** 当 false、其它错误照抛。枢纽原来不响应 PROPFIND，会让你们上传时抛"创建目录失败"。我们会补一个最小合法的 **207 multistatus**（含 `resourcetype`/`getcontentlength`/`getetag`），`testConnection()` 的 `getDirectoryContents('/')` 也会一起走通。
- **收下三个文件**：`playlists.json`（合并）、`settings.json` / `user_apis.json`（整文件旁路）。
- 文件名兜底：`playlists.json` 与 `lx-x-playlists.json` 都能命中，目录名随便填（写错成 `LX_Muisc` 也能用）。

### 2.5 联调时我们会看的

- PUT 的 body 是整份文件（我们按整份解析、缺席即删除），不是增量；
- `meta` 里的未知键不影响你们（我们只回写常用键，原样 id 优先）；
- 若你们有校验（`version` 必须字符串、`data` 必须四键齐全），提前告诉我们。

## 3. 联调验收（双方一起看）

1. 客户端 A 加一首歌 → 客户端 B（同账号、不同设备名）同步后能看到；
2. A 删一首歌 → B 同步后消失；**B 再同步不会把歌推回来**；
3. 两台同类设备各自增删 → **互不误删**（这是设备名存在的唯一理由）；
4. 换一个账号登录 → 看到的是那个账号自己空间的内容，看不到上面这些。

有问题直接说，枢纽侧的改动我们来。感谢配合 🙏
