### 修复

对"本轮被删掉的歌单"不再派生曲目级删除：

```python
for pl in base_keys | cur_keys:
    cur = set(view.get(pl, {}).get("tracks", ()))
    base = set(base_view.get(pl, {}).get("tracks", ()))
    added_t[pl] = cur - base
    if pl in removed_pl:
        removed_t[pl] = set()          # 第九轮：只删歌单，不派生曲目墓碑
    else:
        removed_t[pl] = owned_t.get(pl, set()) - cur
```

与网页端 `delete_playlist()`（只删歌单、不墓碑曲目）语义对齐。

## 取证开关 · `HUB_RAW_PUT_DIR`

`src/hub/api.py::_sync_put` 在鉴权后、解析前落盘原始请求体（默认关闭）：

```powershell
$env:HUB_RAW_PUT_DIR = "<hub>\tmp\raw_put"
Start-Process .\.venv\Scripts\python.exe -ArgumentList '-m','hub.run_fastapi','--host','0.0.0.0','--port','8000' `
  -WorkingDirectory <hub> -WindowStyle Hidden -RedirectStandardOutput tmp\hub_out.log -RedirectStandardError tmp\hub_err.log
```

- 路径：`<HUB_RAW_PUT_DIR>/<客户端键>/<UTC 时间戳>_playlists.json`，每个客户端只保留最近 20 个文件。
- 只在排查时开启；落盘的是用户歌单原文（本机 `tmp/`，不入库、不随空间同步）。
- 同时 `PYTHONPATH` 必须指向 `<hub>\src`（`-m hub.run_fastapi` 靠它找到 `hub` 包）。

## 教训

1. **"缺席即删除"的粒度必须与删除的作用域一致**：歌单级缺席只能删歌单，曲目级缺席才谈得上删曲目——
   跨粒度派生删除会在派生歌单（合并/整理/临时歌单）上血洗来源歌单。
2. **墓碑是全局的**：写错一个曲目墓碑，所有歌单里的同一首歌都会消失；判删前先问"这条删除的作用域是什么"。
3. **只看解析结果不够**：`removed_playlists`/`removed_tracks` 说明枢纽读到了什么，说明不了客户端发了什么；
   要回答后者，必须留下原始请求体。
4. **同一个客户端键上的多来源提交是危险面**：lx 这类不能自定义请求头的客户端没有设备段，
   同一账号的两处使用会合成一个身份，一台的"缺"就是另一台的"删"。
