## §1 浏览器原生弹窗（P0，先复现再改）

### 1.1 现象

用户报告：**改完账号名 / 改完密码之后，弹出的对话框还是浏览器自带的那个**（不是网页自己的弹窗）。

### 1.2 先判定是哪一个（改之前必须做）

打开浏览器 DevTools → Network，复现一次，看两件事：

| 观察到的 | 就是下面哪一条 |
|---|---|
| 有请求返回 **401**，且响应头里有 `WWW-Authenticate: Basic realm="playlist-sync-hub"` | **A：浏览器原生 Basic 认证框**（灰底、要你输用户名密码）→ §1.3 |
| 没有 401，是 Chrome/Edge 右上角"保存/更新密码？"气泡 | **B：密码管理器气泡** → §1.4 |
| 是 `alert()/confirm()` 那种白框 | **C**：先确认——**主会话已全量 grep `webui/src`，`window.alert/confirm/prompt` 为 0 处**，所以 C 基本不存在；若确实见到，把它所在的文件行列出来再改 |

### 1.3 原因 A：401 带了 `WWW-Authenticate`

- 现状（已核实）：认证失败统一走 `src/hub/api.py:496-501` 的 `_unauthorized()`，`:500` 就是 `headers={"WWW-Authenticate": 'Basic realm="playlist-sync-hub"'}`，而它被 **约 30 处**调用点共用——**包括浏览器用的 `/`、`/api/*`**（如 `:634` `/api/spaces`、`:1395` `/api/state`）。浏览器看到该头就会弹原生登录框——**改完密码后前端仍拿旧密码请求，必然 401，于是弹原生框**。
- 改法（最小侵入）：把 `_unauthorized()` 拆成两个：
  - `_unauthorized(webdav: bool = False)`：**只有 WebDAV 同步路由**（`/CyShineMusic/sync-v1.json`、`/ceru/sync-v1.json`、`/d/{device}/...`）才带 `WWW-Authenticate`；
  - 浏览器路由（`/`、`/api/*`、`/assets/*`）的 401 **不带该响应头**，只回 JSON `{"error":"未认证或凭据错误"}`。
  - 细节：只有两处要传 `webdav=True` —— `_sync_get` 的 `:1725`、`_sync_put` 的 `:1813`；其余全部保持默认（不带挑战头）。
  - 理由：栖弦/澜音插件都是**预置** Authorization 头（不需要被 401 挑战），去掉挑战头对它们无影响；而浏览器正是被这个头触发的。
- 前端配套（必须一起做）：
  - 收到 401 时**清掉本地 token 并显示站内登录界面**（`webui/src/App.vue` 已有 `logoutDialog`/`.modal.glass` 这类站内弹窗可复用），**禁止用 `location.reload()` 或跳转触发原生框**；
  - 改密码/改自己账号名成功后：走站内"请重新登录"弹窗（提示用新密码/新账号名），不要直接刷新页面。
  - 自查 `webui/src/lib/api.js` 里所有 `fetch`：401 分支要统一抛 `auth`（部分封装已经这么做了，补齐）。

### 1.4 原因 B：密码管理器气泡

- 改法：给密码输入框加语义化 `autocomplete`：
  - 登录框：`autocomplete="current-password"`；
  - 改密/新增账号：`autocomplete="new-password"`；
  - 账号名输入：`autocomplete="username"` / `off`。
- 这不会完全消除浏览器"是否保存密码"的询问（那是浏览器行为），但能避免"用旧密码覆盖新密码"这种最烦的情况。**如果用户要的是彻底不要这个气泡，只能靠用户在自己的浏览器里关掉该站点的密码提示**——这一条要在汇报里说明清楚，不要承诺做不到的事。

### 1.5 §1 验收

- `curl -i`（或 DevTools）看：`GET /api/state`（不带凭据）→ 401 且**响应头无** `WWW-Authenticate`；`GET /CyShineMusic/sync-v1.json`（不带凭据）→ 401 且**保留** `WWW-Authenticate`。
- 手工：登录 → 改自己密码 → 随便点一个操作 → 出现**站内**提示/登录界面，全程没有浏览器原生框。
- 现有用例不得回归（尤其 `tests/hub/test_hub.py::test_01_auth_required` 断言 401）。

## §2 空间重命名（新功能）

### 2.1 先说清楚：为什么**不能**直接改 pkl 文件名

v3 里空间名 = `space_id` = 成员表/邀请码/`account.space` 的键 = `data/spaces/space__<id>.pkl` 的文件名。如果"改名"实现成"搬文件"，必须同时改：pkl（含 `.bak1/.bak2`）、`_index.json`、`Hub._runtimes` 键、`SpaceRuntime.space_id` 与 `engine.space_id`、`_spaces/_members/_invites` 的键、所有账号的 `space` 指针——任何一步失败就是"空间消失/数据孤儿"，风险远超收益。

### 2.2 推荐方案：**id 不变，只有展示名可变**（改名 = 改一个字段）

- `spaces[id].name` 从此与 `id` 解耦：
  - **字段已经存在**：`config.json:14-21` 就是 `"main": {"name": "main", "kind": "shared", "created_at": ..., "created_by": ...}` ⇒ **不需要任何数据迁移**，只是以前没人改过这个字段、也没人读它做展示；
  - **老空间**：`id` 仍是当年的名字（现有 `spaces[*].name == id` 天然满足），历史数据一个字节都不动；
  - **新空间**：`id` = 创建时用的名字（同样的 `_valid_space_name` 校验，见 `:294`），之后可以改名。
- **重命名只改 `spaces[id].name`**：不搬 pkl、不动 `members`/`invites`/`account.space` 的键、不动 `_runtimes`。
- 客户端**零影响**：WebDAV 地址里本来就没有空间名（`/CyShineMusic/sync-v1.json`），**所有人都不用改地址**。
- 代价（要在文档里承认）：`id` 与 `name` 可能不一致（`id` 是历史痕迹）；API 路径参数需要同时接受两者。

### 2.3 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| PUT | `/api/spaces/{name}/rename` | 该空间 owner 或全局 admin | body `{"new_name": "..."}`；成功 `{"ok":true,"space":<id>,"name":<new_name>}` |

- 与既有 `/api/users/{name}/rename` 风格一致（`body.new_name`）。
- `{name}` 允许传 **id 或当前展示名**（见 §2.4 解析规则）。

### 2.4 空间解析（新增一个 helper，所有空间路由统一用它）

```python
def _find_space(token: str) -> Optional[str]:
    """token 命中 id → 返回该 id；否则在所有 spaces 的 name 里唯一命中 → 返回其 id；
    命中多个或有歧义 → 返回 None（调用方回 404/409）。"""
```

- 应用点：`DELETE /api/spaces/{name}`（`:644`）、`GET/PUT/DELETE /api/spaces/{name}/members[...]`（`:905`/`:922`/`:953`）、新增的 `/api/spaces/{name}/rename`、以及 `PUT /api/users/{name}/space`（`:729`）与 `POST /api/invites`（`:991`）的 `space` 参数。
- 兼容要求：**传 id 必须永远有效**（老前端/老脚本不受影响）。

### 2.5 校验与不变量

1. `_valid_space_name(new_name)`（`src/hub/api.py:294`）→ 否则 400；
2. 新名**不得等于任何已存在空间的 id**，也**不得等于其他空间的展示名** → 否则 409「名字已被占用」；
3. `new_name == 当前 name` → 直接 200（幂等，不写审计）；
4. 权限不足 → 403「仅空间管理员可重命名」；
5. 空间不存在 → 404；
6. 不变量①不受影响（键没变）；**`account.space` 仍然存 id**，不要改成 name——否则所有同步路由都要跟着改。

### 2.6 展示层（要做全，否则会出现"改名了但界面还显示旧名"）

- `_space_summary()`（`src/hub/api.py:399`）：返回里**加 `"name"`**（现在只有 `space`），`space` 保持 id 不变；
- `/api/state`（`src/hub/api.py:1391`）：空间信息里带 `name`；
- 成员列表 / 邀请码列表：带 `space`（id）与 `space_name`（展示名）；
- 前端：**显示 `name`，回退 `space`**；切换空间、退出空间、加入空间、空间管理、邀请码等所有出现空间名的地方都要走同一个显示函数（建议在 `webui/src/lib/` 加一个 `spaceLabel(s)`）。
- `space_quota`、孤儿空间（只有磁盘记录、无元数据）→ 显示 id。

### 2.7 审计

`_audit("space.rename", actor, <id>, f"{old_name} → {new_name}")`；日志一行。

### 2.8 §2 验收用例（`tests/hub/test_spaces_http.py` 追加 5 条）

1. `test_22_owner_can_rename_space`：owner 改名 → 200，`GET /api/spaces` 里该空间 `name` 变、`space`(id) 不变，**pkl 文件名不变**；
2. `test_23_rename_keeps_sync_working`：改名后该空间成员的同步 GET/PUT 仍 200，歌单数据不变（**关键：不能因为改名把数据弄丢**）；
3. `test_24_rename_rejects_duplicate_or_invalid`：与别人 id/name 冲突 → 409；`../x`、空、`space__x` → 400；
4. `test_25_rename_requires_owner`：普通成员 → 403；非成员 → 404（按解析结果）；
5. `test_26_routes_accept_id_or_name`：`GET /api/spaces/{新名}/members` 与 `GET /api/spaces/{id}/members` 都 200 且内容一致。

### 2.9 文档
