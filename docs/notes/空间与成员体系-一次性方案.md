## 0 结论（先看这四条）

| 问题 | 拍板 | 一句话理由 |
|---|---|---|
| 要一次性做好吗？ | **是**，按本文一次做完（后端 + 前端 + 用例 + 文档） | 现在缺的入口/权限散在 5 个地方，分批做会改 4 次数据模型 |
| 普通账号要不要能新建空间？ | **要**，建完自动成为该空间 owner，配额 3，可开关 | 新建是"纯增量、不碰别人数据"的操作，卡它只会让管理员变瓶颈；**加入别人的空间才是侵入性操作**，必须邀请码 |
| 用空间角色还是邀请码？ | **两个都要，但分工不同**：角色管"进了空间之后能做什么"，邀请码管"怎么进这个空间" | 只有邀请码没有角色 → 没法做只读成员；只有角色没有邀请码 → 还是靠猜名字加入 |
| 扩展性怎么留？ | **多对多成员表 + 账号上的"当前空间"指针** | 同步端点靠 Basic 账号认证、地址里没有空间，所以"账号当前只生效一个空间"是硬约束；用指针满足它，用成员表留住"以后一台设备进多个空间"的可能 |

**本方案不碰**：同步端点语义、引擎合并规则（R1 / I2′ / GC 例外 / 安全阀）、空间 pkl 结构与文件名。

## 1 数据模型（config.json v3）

`src/hub/api.py` 现在落盘 `{"version": 2, "accounts": {...}}`（`_persist_accounts()`）。升级为：

```json
{
  "version": 3,
  "accounts": {
    "alice": {"password": "pbkdf2$...", "role": "admin", "space": "alice",
              "enabled": true, "created_at": "...", "updated_at": "..."}
  },
  "spaces": {
    "alice":  {"name": "alice",  "kind": "personal", "created_at": "...", "created_by": "alice"},
    "home":   {"name": "home",   "kind": "shared",   "created_at": "...", "created_by": "alice"}
  },
  "members": {
    "alice": {"alice": {"role": "owner", "joined_at": "...", "invited_by": ""}},
    "home":  {"alice": {"role": "owner", "joined_at": "...", "invited_by": ""},
              "bob":   {"role": "editor", "joined_at": "...", "invited_by": "alice"}}
  },
  "invites": {
    "K7QM3XTP": {"space": "home", "role": "editor", "created_by": "alice",
                 "created_at": "...", "expires_at": "...", "max_uses": 1, "uses": 0,
                 "note": "给妈妈的手机"}
  },
  "policy": {
    "user_create_space": true,
    "max_owned_spaces": 3,
    "allow_self_register": true,
    "member_invite": false
  }
}
```

字段口径：

- `spaces[<space_id>].name` —— 展示名，**本期恒等于 space_id**（保留字段是为了以后做"稳定 id + 可改展示名"）。
- `spaces[*].kind` —— `personal`（个人空间，账号名 == 空间名）／`shared`（多人共用）／`orphan`（磁盘上有数据但已无成员，运行时按磁盘列出来判定，不必写进表）。
- `members[<space>][<account>].role` —— `owner` / `editor` / `viewer`。
  - `owner`：空间管理员。可加/移成员、改角色、生成邀请码、确认本空间任何待办卡、删空间。
  - `editor`：正常同步与网页改歌单（默认加入者的角色）。
  - `viewer`：**只读**。GET 同步端点可以（设备能拉歌单），一切写操作 403。
- 全局 `accounts[*].role`（`admin` / `user`）**保持不变**，与空间角色是两个维度：全局 admin 对任何空间都有 owner 级权限（枢纽运营者）。
- 不变量（实现里必须保证）：
  1. `accounts[*].space` 必须指向一个存在的 `spaces` 键，且该账号在 `members[该空间]` 里。
  2. 每个非孤儿空间**至少一个 owner**。
  3. `invites[*].role` 只能是 `editor` / `viewer`（不允许用邀请码造 owner）。

## 2 迁移 v2 → v3（启动时自动、幂等、可回滚）

在 `run_fastapi.py` 读 `config.json` 之后、`configure()` 之前（或 `api.configure()` 内）执行：

```
读入 accounts（v2 或 v3）。
若 version < 3：
  1) spaces / members 置空。
  2) 对每个账号 acc，space = accounts[acc].space or acc：
       spaces.setdefault(space, {"name": space,
                                 "kind": "personal" if space == acc else "shared",
                                 "created_at": acc.created_at, "created_by": acc})
       members.setdefault(space, {})[acc] = {
           "role": "owner" if space == acc else "editor",   # 房间主人=账号名同名者
           "joined_at": acc.created_at, "invited_by": ""}
  3) 兜底：任何 space 若一个 owner 都没有 → members[space][首个全局管理员] = {"role": "owner", ...}
       （没有管理员则取账号表第一项）。
  4) policy 缺失则填默认值（§1）。
  5) version = 3，落盘（原子写 + .bak1/.bak2 滚动）。
```

要点：

- **不动任何 pkl**，不动 `accounts[*].space` ⇒ 迁移后同步行为与迁移前逐字节等价（这是最重要的验收点）。
- v3 读入时若 `members` 缺失但 `accounts` 有 `space`，按上面第 2 步补齐（幂等）。
- 磁盘上存在但账号表里没有的空间 = **孤儿空间**，只在 `GET /api/spaces`（管理员）里按磁盘列出，`orphan: true`，不写进 `spaces` 表；管理员可用现有 `DELETE /api/spaces/{name}` 删除（已实现，语义不变）。

### 3.1 我（前端启动用）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/me` | 登录 | `{name, is_admin, global_role, space(当前), spaces:[{space, role, name}], policy:{can_create_space, max_owned_spaces}}`。前端从此不再自己推导身份 |

### 3.2 空间

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/spaces` | 登录 | **改造**：普通账号返回**自己是成员的全部空间**（原来只有当前那一个）；管理员额外返回全部空间与孤儿空间。每项：`{space, name, my_role, members:[{name,role}], playlists, revision, exists, orphan, is_current}`。**不返回歌单内容** |
| POST | `/api/spaces` | 登录（`policy.user_create_space`） | **改造**：允许普通账号；校验配额 `max_owned_spaces`（管理员不限）→ 超限 409；空名/非法字符 400；重名 409；创建者是 owner；body 可带 `{"current": true}`（默认 true）表示顺手切过去 |
| DELETE | `/api/spaces/{name}` | 该空间 owner 或全局 admin | **改造**：由"仅管理员 + 仅孤儿"放宽为"owner 可删自己的空间"，但仍要求**除自己外无其它成员**（有则 400 并列出成员）；路径穿越防护与 `space__` 前缀校验保留 |

### 3.3 成员

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/spaces/{name}/members` | 该空间成员 | 成员列表（名字 + 角色 + 加入时间 + 邀请人） |
| PUT | `/api/spaces/{name}/members/{account}` | owner / 全局 admin | body `{"role": "editor"\|"viewer"}`；**不能把最后一个 owner 降级**（400） |
| DELETE | `/api/spaces/{name}/members/{account}` | owner / 全局 admin（移别人）；自己用 leave | 移除成员；被移除者若当前空间正是这里 → 自动切回自己的个人空间（见 §3.5） |

### 3.4 邀请码

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/invites` | owner / 全局 admin；（`policy.member_invite=true` 时 editor 也可以） | body `{space?, role="editor", expires_in_hours=24, max_uses=1, note?}`。space 默认当前空间；role 只允许 editor/viewer；返回 `{code, space, role, expires_at, max_uses}` |
| GET | `/api/invites?space=` | 同上 | 列出有效码（含剩余次数、到期时间、创建者）。**码只对 owner/管理员可见** |
| DELETE | `/api/invites/{code}` | 创建者 / owner / 全局 admin | 撤销（置 `disabled: true`，保留记录便于审计） |
| POST | `/api/join` | 登录 | body `{code}`。校验：存在、未撤销、未过期、`uses < max_uses` → 写 membership（已存在则更新角色但不降级）+ 把 `accounts[me].space` 指向该空间 + `uses += 1`；返回 `{ok, space, role}`。失败统一 400 并给明确中文文案（"邀请码不存在/已撤销/已过期/已用完"） |
| POST | `/api/register` | **不需要登录**（`policy.allow_self_register`） | body `{name, password, code}`。**邀请码即注册许可**：校验码 → 建账号（全局 role=user，`space`=码里的空间，直接成为其成员，角色取码里的 role；**不建个人空间**）；名字已存在 409（提示"已注册？请登录后用邀请码加入"）；名字/密码校验复用建号规则 |

### 3.5 我自己

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/me/space` | 登录 | body `{space}`。**切换当前空间**：必须是自己的 membership（否则 403）；从此取代"普通账号不能切空间"的限制。管理员代管别人仍走 `PUT /api/users/{name}/space`（保留） |
| POST | `/api/me/leave` | 登录 | body `{space}`。退出该空间：删 membership；若退的是当前空间 → 自动切回自己的个人空间（账号名同名空间，不存在则自动建并把该账号设为 owner）；**唯一 owner 不能退**（400，先转移） |

## 10 明确不做（并说明为什么）

| 不做 | 理由 | 以后要做的入口 |
|---|---|---|
| 空间改名 | ~~空间名 = space_id = pkl 文件名 = WebDAV 地址语义，改名等于搬迁~~ **已支持**（第三轮）：展示名与 id 解耦，`spaces[*].name` 可改、id/pkl/地址不变，API 用 `_find_space` 同时接受 id 或展示名 | `PUT /api/spaces/{name}/rename` + `_find_space`（2026-10-07 已落地） |
| 稳定 space_id（与名字解耦） | ~~收益（改名、重名）现在不需要，代价是所有路径/文件要迁移~~ **已支持**（第三轮） | 同上（id 稳定不变，仅展示名可变） |
| 路径带空间（`/s/{space}/...`） | 会立刻引入"路径空间 vs 账号空间"的授权校验（安全边界），且没有"一个账号同时进两个空间"的需求 | 成员表已支持多空间，届时加"每设备指定空间"的映射即可 |
| 空间级主题/音源默认值 | opaque 已按客户端分桶（各设备各一份），够用 | `spaces[*].opaque_default` |
| 邀请码二维码/批量/一次性链接 | 一期用不到 | `invites` 表加字段即可 |
| 账号自助删除 | 不是当前痛点 | `/api/me/delete` |

## 11 落地顺序（一个 PR 的推荐提交顺序）
