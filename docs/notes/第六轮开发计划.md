### 1.3 注册表字段（骨架）

```python
@dataclass(frozen=True)
class RenderContext:
    view: dict
    meta_pool: dict
    native_ids: dict
    pending_cleanup: Optional[list]
    opaque: dict
    opaque_tracks: Optional[dict]
    revision: int
    generated_at: str
    playlist_times: dict          # {pl_id: {"created_at":…, "updated_at":…}}

@dataclass(frozen=True)
class Dialect:
    name: str                     # "cyshine-v1" —— 引擎/存储里用的稳定 id，不许改
    roots: tuple                  # 路径第一段白名单，如 ("CyShineMusic",)
    files: tuple                  # 文件名，如 ("sync-v1.json",)
    parse: Callable               # (payload) -> (submission, meta_delta, opaque, warnings)

    empty_view_on_no_baseline: bool = False
    file_fallback: bool = False   # 见 §1.4
```

## §2 任务包 B：洛雪（lx-x）客户端适配器

### 2.1 客户端与样例文件事实（实测，别猜）

两份真实文件都在 `D:\Alist\music\`（洛雪经 Alist WebDAV `https://yechoy.cn/dav/music` 同步上来的）：

| 文件 | 大小 / 时间 | 说明 |
|---|---|---|
| `D:\Alist\music\LX_Muisc\playlists.json` | 866,956 B / 2026-10-01 15:14 | **客户端实际写入的那种外形**：顶层 5 键 `version / lastModified / data / playHistory / downloadTasks` |
| `D:\Alist\music\lx-x-playlists.json` | 137,005 B / 2026-10-06 18:55 | 同 schema 的精简导出（无 `playHistory`/`downloadTasks`，三张个人列表为空） |

- `version = "2"`（**字符串**，回写也要是字符串）、`lastModified` = epoch 毫秒；UTF-8、**单行** JSON。
- `data` 四键的**元素类型不固定**（关键坑）：
  - `defaultList` / `loveList` / `tempList` = **曲目数组**（真文件 722 / 232 / 301 首）
  - `userList` = **歌单数组**（真文件 2 个：`tx_32c57f1de8258842602240a7c3920333`(`YHK`, 114 首)、`userlist_1782378881351`(`纯音乐`, 17 首)）
- 曲目字段：`{id, name, singer, source, interval, meta}`（少数带 `alias/artists`）；`interval` 形如 `"03:55"`；`id` 形如 `tx_002xEHdK35q6Qp`（`<source>_平台ID`）。
- 真文件（1386 首）统计：音源 **tx 1169 / wy 69 / kw 99 / kg 49**；`meta` 常见键 `songId/albumName/albumId/picUrl/qualitys/_qualitys`，**必须容忍未知键**（`strMediaMid/albumMid/id/hash/fee/mv/_full/…`）。
- **`<source>_` 前缀不是普遍规律**：1337/1386 有，**49 首 kg 老格式没有**（`545879713_E3426FF0609426305A4A4BB9DC2AD29B`），且这 49 首**没有 `meta.strMediaMid`**（只有 `meta.hash`）⇒ 见 §2.2。
- 歌单对象是 `{id, name, list, locationUpdateTime}`，导入/聚合出来的还带 `source` + `sourceListId`（**原样透传，别丢**）。
- 提交与交付都是**整份文件**，不是增量；**不要用纯数字 id 做身份**（跨音源会撞车，见工作区 `LX澜音歌单对比工具\README.md:34-40`）。

### 2.2 身份映射规则（`parse_lx`）

```
platform_id = 顶层 id 以 "<source>_" 开头 → 去掉该前缀，否则**原样用顶层 id**
              （只有顶层 id 缺失/为空时才退到 meta.strMediaMid || meta.songId || meta.songmid || meta.hash || meta.copyrightId）
source      = song.source || meta.source        # source 也可能只在 meta 里
```
理由：顶层 `id` 就是**洛雪自己的身份**。**49 首 kg 老格式**（`545879713_E342…`：无 `kg_` 前缀、无 `strMediaMid`、有 `hash`）如果按官方导入插件的 hash 优先序重算，会得到一个与洛雪不同的 id，回写后洛雪可能当成新曲目 —— 所以这里以顶层 id 为准，并记下**原样 id**（`meta_delta[...]["lx_native_id"]`），交付时原样回写洛雪给的那个字符串（不改写、不补前缀）。
与官方导入插件 `CeruMusic-Plugin-Template-fork\plugins\ceru.lx-playlist-import\plugin.js:2480-2488`（hash→songmid→copyrightId→songId）的差异只影响那 49 首 kg 曲目，可能表现为"同一首在澜音/洛雪算两条" ⇒ 记 §2.8 第 4 条，联调确认。

- 无法确定 `source` 或 id 的曲目：**不许丢**，按 I6 原样进 `opaque["tracks"][native_id]`（照 `src/hub/adapters.py:111-117` cyshine 的做法），渲染时回填。
- 非白名单音源（`wy/tx/kw/kg/mg` 之外，例如本地文件 / 其它插件）：同上走 opaque，只计数 + `warnings`。
- `meta_delta[identity_key(source, platform_id)]` 写：`title`（`name || title`）、`singer`、`album`（`meta.albumName`）、`duration_ms`（`interval` → 毫秒）、`quality`（`qualitys/_qualitys` 里最高一档）、`pic_url`（`meta.picUrl`），另存**洛雪专用**回写字段：`lx_native_id`（原样 id）、`lx_num_id`（`meta.id`，为 0 时不写）、`lx_str_media_mid`、`lx_song_id`。缺失字段不覆盖已有值（沿用 cyshine 的 `if v is not None and k not in merged` 写法）。
- `interval` 解析：照官方 `plugin.js:2471-2479`，`split(":")` 最多 3 段、每段数字 → `total*60+秒` ×1000。

### 2.3 线格式（提交 / 交付都由我们定，洛雪不用改）

- **提交（PUT）**：就是洛雪原文件的外形 —— `{"version":"2","lastModified":<int>,"data":{defaultList,loveList,tempList,userList},"playHistory":[…],"downloadTasks":[…]}`（后两键在精简导出里没有）。
- **交付（GET）**：同外形，逐键还原：
  - `version` 仍写**字符串** `"2"`；`lastModified` 写"引擎 stamp 的 epoch 毫秒"（`generated_at` 是 ISO8601，需转换）；**内容不变则同值**（保持既有"确定性交付"约定）。
  - `data.userList` = 枢纽合并结果；歌单对象 `{id, name, locationUpdateTime, list}`，`id` 用该歌单在本客户端的 native id（首次提交写入 `store.native_ids("lx-x")`；枢纽新建的歌单没有 native id → 用枢纽 id，并允许洛雪下次提交时换回它自己的 id），`origin`/`source`/`sourceListId` 等附加键按 native id 从 opaque 还原（§2.4）。
  - 只写洛雪认识的键；**不加额外的顶层/曲目键**（避免它校验失败）。
- 曲目回写：`id` **优先用 `meta_pool[key]["lx_native_id"]` 原样输出**；没有时（这首歌是澜音/栖弦带进来的）再合成 `f"{source}_{pid}"`。其余 `{"name": title, "singer": "、".join(artists), "source": source, "interval": "mm:ss"（≥1 小时写 h:mm:ss）, "meta": {"songId": <lx_song_id 或 pid>, "strMediaMid": <lx_str_media_mid 或 pid>, "albumName":…, "albumId":…, "picUrl":…, "qualitys":[{"type": <最高档>}]}}`。

### 2.4 三张"非歌单"列表：走 opaque，不进合并（**关键**）

**按客户端分桶**存进 `opaque_by_client[cid]`（D23），渲染时原样还给**同一台客户端**：

```
opaque = {
  "lx_lists": {"defaultList":[…722], "loveList":[…232], "tempList":[…301]},
  "lx_extra": {"playHistory":[…18], "downloadTasks":[…]},          # 顶层其余键，未知键也要收
  "lx_playlist_extras": {native_id: {"origin":…, "source":…, "sourceListId":…}},
  "tracks": {native_id: <无法定身份的曲目原文>},
}
```

- 提交侧：`parse_lx` 的第 3 个返回值；`src/hub/api.py:2009-2012` 已经会把非空 `opaque` 落到 `rt.opaque_by_client[cid]`。
- 交付侧：`src/hub/api.py:1962-1969` 已实现"按客户端取桶"，`render_lx` 读 `ctx.opaque` 原样输出；空/缺失时输出 `[]` / `{}`。
- 理由：这三张表是"本机个人数据"（真文件里 722/232/301 首），一旦进合并会被别人的空值清空（和澜音主题/音源同一类问题）；`playHistory`/`downloadTasks` 与歌单同步无关，丢了是纯数据损失。
- **只有 `data.userList`（用户自建歌单）参与合并。**

### 2.5 歌单身份与顺序

- `native_id = str(userList[i].id)`（如 `tx_32c57f1de8258842602240a7c3920333`、`userlist_1782378881351`）；`name` 参与同步，允许重名（枢纽侧已支持）。
- 曲目顺序按 `list` 原样（枢纽保留顺序）。
- 歌单附加键（`origin` / `source` / `sourceListId` / `locationUpdateTime`）不参与合并，按 §2.4 的 `lx_playlist_extras` 透传；枢纽新建的歌单给 `origin="created"`、`locationUpdateTime=null`。

### 2.6 能力表

```python
CAPABILITIES["lx-x"] = {"delete_track": True, "delete_playlist": True,
                        "create_playlist": True, "reorder": False}
```

理由与前提：洛雪提交的是**整份**歌单文件（每个歌单都带完整 `list`），"缺席即删除"在语义上成立，与 D26（澜音按可删处理）同一逻辑。**若联调发现洛雪只上报增量/局部歌单，回退方式是一行**：`delete_track/delete_playlist` 改回 `False`（此时被删内容只会进交付里的 `cleanup` 提示，不会自动删本地）。
`reorder=False`：洛雪文件里没有可用的顺序变更信号，保守。

## §3 任务包 C：设备身份（多设备 / 多端同账号）

### 3.1 为什么必须做（会真丢数据）

### 4.1 要解决的两个问题
