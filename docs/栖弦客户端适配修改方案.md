# 栖弦（CyShineMusic）客户端适配修改方案

> 对接枢纽：`playlist-sync-hub`（自建 WebDAV 同步服务）
> 最后更新：2026-10-09
> 枢纽侧已修复的问题：cyshine 适配器 songId int→str 转换、appearance/musicSources 默认值补 modifiedAt

---

## 一、必须改（阻塞正常同步）

### 1. viewer（只读）账户 PUT 403 未区分

**现状**：`webdav_client.dart L125` 把 401（未认证）和 403（已认证但无权限）同等对待，统一抛 `WebDAVException('WebDAV 用户名、密码或权限不正确')`，直接终止整个同步流程。

**问题**：viewer 账户权限为"只读"，枢纽对其 PUT 请求返回 403 是正确行为，但栖弦把 403 当成致命错误，导致 viewer 账户**连 GET 拉取也无法完成**（同步流程 GET→merge→PUT 中 PUT 抛异常后 GET 结果也被丢弃）。

**修改**：`webdav_client.dart` 的 `_statusException` 方法，区分 401 和 403：

```dart
// 修改前
401 || 403 => WebDavException('WebDAV 用户名、密码或权限不正确', statusCode: status),

// 修改后
401 => WebDavException('WebDAV 用户名或密码不正确', statusCode: status),
403 => WebDavException('WebDAV 账户为只读模式，无法推送本地改动', statusCode: status),
```

同时在同步流程中捕获 PUT 的 403，**跳过 PUT 但保留 GET 结果**：

```dart
// sync 流程中 PUT 失败处理
try {
  await client.putSnapshot(mergedSnapshot);
} on WebDavException catch (e) {
  if (e.statusCode == 403) {
    // viewer 账户：跳过推送，继续后续流程
    debugPrint('同步：账户只读，跳过推送');
  } else {
    rethrow;  // 其他错误继续抛
  }
}
```

**影响**：viewer 账户登录后能正常拉取云端歌单，只是本地改动不会推上去。

---

### 2. 同步循环缺尾随 GET

**现状**：栖弦同步流程是 `GET → 本地 merge → PUT`，PUT 后即结束。

**问题**：PUT 完后枢纽已经合并了其他设备的最新改动，但栖弦**不会再拉一次**——甲端刚加的歌，乙端要等下一次手动同步/重启应用才能看到。

**修改**：PUT 成功后追加一次 GET，拿枢纽的权威合并结果直接应用：

```dart
// 修改前
await _syncOnce();  // GET → merge → PUT → 结束

// 修改后
await _syncOnce();  // GET → merge → PUT
// 追加尾随 GET
final finalSnapshot = await client.getSnapshot();
await ref.read(localPlaylistsProvider.notifier).applyFromSync(finalSnapshot.playlists.data);
await ref.read(musicSourceControllerProvider.notifier).applyFromSync(finalSnapshot.musicSources.data);
// appearance 的 apply（见第 3 点）
```

**效果**：任何一端本地改动后，2-3 秒内就能把其他设备的最新状态也带回来，用 push 的频率实现准实时 pull。

---

### 3. appearance（外观设置）缺 apply 分支

**现状**：`webdav_sync_controller.dart` 的 `_applyRemoteSections` 只对比并 apply `playlists` 和 `musicSources` 的 hash，**完全漏了 appearance**。

```dart
// 修改前
if (syncDataHash(local.playlists.data) != syncDataHash(merged.playlists.data)) {
  await ref.read(localPlaylistsProvider.notifier).applyFromSync(merged.playlists.data);
}
if (syncDataHash(local.musicSources.data) != syncDataHash(merged.musicSources.data)) {
  await ref.read(musicSourceControllerProvider.notifier).applyFromSync(merged.musicSources.data);
}
// ← 这里缺 appearance 的 apply！
```

**修改**：加上 appearance 的 apply 分支：

```dart
final localAppearance = ref.read(settingsProvider);
if (syncDataHash(localAppearance) != syncDataHash(merged.appearance.data)) {
  await ref.read(settingsProvider.notifier).applyFromSync(merged.appearance.data);
}
```

**效果**：主题/外观设置跨端同步生效。

## 二、建议改（消除两层合并风险）

### 4. 去掉客户端本地 merge，完全信任枢纽

**现状**：栖弦 `_mergeLocalAndRemote` 按 `modifiedAt` 时间戳取新者，与枢纽的 R1 合并引擎**两层叠加**。

**风险**：设备时钟漂移/跨时区时，两端判新旧可能不一致，导致诡异的丢歌或复活。

**修改**：把 `_mergeLocalAndRemote` 改成**简单覆盖**——直接用枢纽渲染结果替换本地：

```dart
// 修改前：本地 merge + 时间戳判新旧
Future<WebDavSyncSnapshot> _mergeLocalAndRemote(WebDavSyncSnapshot remote) async { ... }

// 修改后：直接用远端替换本地
Future<WebDavSyncSnapshot> _mergeLocalAndRemote(WebDavSyncSnapshot remote) async {
  // 本地作为 PUT 的初始快照（包含本地还没推上去的改动）
  // 但 GET 的结果 = 枢纽的权威合并，直接应用
  return remote;
}
```

**理由**：枢纽已经是唯一的合并者，客户端不需要再做第二套 merge。

---

### 5. 去掉 etag/If-Match 并发保护（死代码清理）

**现状**：栖弦 GET 时发送 `If-Match`，期望枢纽返回 304。

**问题**：枢纽**永不返回 304**（栖弦把非 2xx 当失败，所以枢纽每次都返回 200），etag 逻辑形同虚设。

**修改**：清理 `webdav_client.dart` 中 etag/If-Match 相关代码，简化 GET 请求。

---

### 6. 回前台触发同步

**现状**：栖弦只在用户手动点同步时才拉取，切后台半天回来数据是旧的。

**修改**：在 Flutter 的 `AppLifecycleState.resumed` 钩子触发一次同步：

```dart
WidgetsBindingObserver.didChangeAppLifecycleState 中：
if (state == AppLifecycleState.resumed) {
  syncService.triggerSync();
}
```

## 三、可选优化（效率提升）

### 7. PUT 前 hash 比对，跳过无变更提交

**现状**：每次改一首歌就 PUT 整个 `sync-v1.json`，枢纽重新解析 + merge。

**修改**：栖弦存一个 `last_upload_hash`，本地快照 hash 没变就跳过 PUT。

```dart
final currentHash = syncDataHash(localSnapshot.toJson());
if (currentHash == _lastUploadHash) {
  debugPrint('同步：本地无变更，跳过 PUT');
  return;
}
_lastUploadHash = currentHash;
await client.putSnapshot(localSnapshot);
```

---

### 8. debounce 时间加长到 3-4 秒

**现状**：栖弦 debounce 2 秒。

**问题**：新建歌单 + 加歌时，本地数据库异步写可能还没完成，2 秒就抓快照 → 抓到歌单壳子但曲目为空 → PUT 空歌单壳子。

**修改**：debounce 加长到 3-4 秒，或者快照捕获时重试直到曲目列表非空。

## 四、接口契约（栖弦 ↔ 枢纽）

### 枢纽返回的 GET 结构（栖弦已正确解析）

```json
{
  "schemaVersion": 1,
  "generatedAt": "...",
  "sections": {
    "playlists":    { "modifiedAt": "...", "data": [...] },
    "appearance":   { "modifiedAt": "...", "data": {...} },
    "musicSources": { "modifiedAt": "...", "data": {...} }
  }
}
```

**硬约束**：每个 section 必须同时有 `modifiedAt` 和 `data` 字段（枢纽已确保）。

### 栖弦提交的 PUT 结构（枢纽已正确解析）

```json
{
  "schemaVersion": 1,
  "generatedAt": "...",
  "sections": {
    "playlists":    { "modifiedAt": "...", "data": [...] },
    "appearance":   { "modifiedAt": "...", "data": {...} },
    "musicSources": { "modifiedAt": "...", "data": {...} }
  }
}
```

**曲目身份键**：`source:songId`（songId 可以是 int 或 str，枢纽 cyshine 适配器已统一处理）。

### HTTP 状态码语义

| 状态码 | 含义 | 栖弦处理 |
|---|---|---|
| 200 | 成功 | 正常处理 |
| 401 | 用户名/密码错误 | 提示用户检查凭据 |
| 403 (GET) | 非空间成员 | 提示用户加入空间 |
| **403 (PUT)** | **viewer 只读** | **跳过 PUT，保留 GET 结果继续**（必须改） |
