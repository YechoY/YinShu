# 🎵 音枢 Yinshu

> 一个**跨播放器的歌单同步枢纽**：你的多台设备、多个播放器、甚至朋友的账号之间，歌单互通。

<div align="center">

```
   🎵 栖弦        🎧 LX-X        🎹 澜音
      │              │              │
      ↕ 双向同步      ↕ 双向同步      ↕ 双向同步
      │              │              │
      └──────┬───────┴───────┬──────┘
             │               │
         🧩 音枢枢纽
```

**各自新增会合并，各自删除会传播，分钟级生效。**

🚧 v0.1.0 beta · 🧪 146 条测试全绿 · 🐍 Python 3.10+ · ⚖️ 非商用许可

</div>

**目前支持的客户端**：🎵 **栖弦（CyShineMusic）** 和 🎧 **LX-X**（洛雪系第三方衍生版，注意与官方「洛雪 LX Music」不是同一个项目）已完成真机双向同步验证；🎹 **澜音（CeruMusic）** 的服务端适配已就绪，正等上游插件 SDK 补充后做真机验证。接入新客户端只需新增一个适配器文件，无需改引擎或服务端代码。

## ⏱ 3 秒看懂

**实例 1：加一首歌，另一台播放器跟着出现**

```
📱 你在栖弦的歌单「深夜食堂」里加了一首《海阔天空》 → 点同步
🔄 音枢收到，翻译成统一格式，合并入库
🎧 10 秒后，LX-X 里「深夜食堂」也出现了《海阔天空》
```

**实例 2：删一首歌，另一台播放器跟着消失**

```
🎧 你在 LX-X 里删掉《无聊》 → 点同步
🔄 音枢一看：这个歌单 updatedAt 变了、歌不见了 → 判定为删除
📱 栖弦同步后，《无聊》也从歌单里消失了
```

就这两件事——**加**和**删**——音枢在中间负责"翻译 + 合并"，让各家播放器步调一致。

## 🤔 为什么要造这个东西？

你有没有过这种经历：

- 手机上同时装了栖弦和 LX-X，歌单各管各的，加了歌那边看不到
- 想跨平台同步歌单，结果每家都是自己的私有格式，互相不认
- LX-X 官方同步只能手动选"覆盖方向"，没有真正的双向合并

**音枢**就是来解决这个的。它跑在你自己的服务器或本机上，做两件事：

1. **🌐 翻译**：每家客户端的 WebDAV 格式不一样？没关系，音枢接进来统一成内部格式，对外再翻译回去
2. **🧩 合并**：两端各有增删？音枢做增量合并，不会丢数据。**删除就是删除，加回来就是加回来**

客户端**零改动**，只需要把同步地址改成音枢的 URL。

## 🎯 能拿来做什么？

**场景 1：同一个 App，手机和平板歌单互通**
📱 家里平板和手机都装栖弦？都登**同一个音枢账号**就行——手机上加的歌，平板同步一下就有；平板上删掉的歌单，手机也不会再出现。LX-X 同理。

**场景 2：栖弦和 LX-X 之间互相搬运**
🔄 栖弦和 LX-X 的歌单各管各的？两个客户端连**同一个音枢账号**，栖弦加的歌 LX-X 能看到，LX-X 删的栖弦也会跟着删——不用手动导出导入。

**场景 3：和朋友共建歌单，"一起听"**
👥 建一个**共享空间**，把朋友的账号拉进来。之后你俩在这个空间里加的歌，对方同步一下就有，相当于共同维护一份歌单。各自私密的歌单放在自己的空间里，互不打扰。

> 每个账号天生有一个自己的空间；共享空间在管理界面里创建，朋友用邀请码加入即可。

## 🚀 快速开始（约 2 分钟）

### ① 安装 uv（如果还没装）

```bash
# Windows / macOS / Linux 都行
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### ② 一键启动

**Windows**（PowerShell）：

```powershell
git clone https://github.com/YechoY/yinshu.git yinshu
cd yinshu
.\run.ps1
```

**Linux / macOS / WSL**：

```bash
git clone https://github.com/YechoY/yinshu.git yinshu
cd yinshu
./run.sh
```

脚本会自动装好 uv、配齐依赖、启动服务，真正的开箱即用。也可以手动执行 `uv run yinshu`（效果相同）。

🎉 搞定！启动后浏览器会自动打开 http://127.0.0.1:8000/ 管理界面（服务器环境加 `--no-open` 关闭）。默认账号 `admin` / `admin123`（仅本机测试，记得去管理界面改密码）。

### ③ 让音乐客户端连上来

不用拼任何路径——客户端只填**枢纽的根地址** + 音枢的账号密码，它们自己会请求自己的文件，音枢靠路径自动识别是哪家客户端：

| 客户端 | 同步设置里填什么 |
|--------|----------------|
| 🎵 栖弦 (CyShineMusic) | WebDAV 地址填 `http://<你的服务地址>`（客户端自己拼 `/CyShineMusic/...`） |
| 🎧 LX-X（洛雪系衍生版） | WebDAV 地址填 `http://<你的服务地址>`（目录随便它建，音枢按文件名识别） |
| 🎹 澜音插件 | 服务器地址填 `http://<你的服务地址>`（插件自己拼 `/ceru/...`） |

> `<你的服务地址>` 可以是本机 `127.0.0.1:8000`、局域网 `192.168.x.x:8000`，
> 也可以是部署到服务器后的域名（如 `https://yechoy.cn`）。
> 同一台服务器的多台设备想各自独立基线？地址写成 `http://<服务地址>/d/<设备名>` 即可，不写也能用。

认证方式：HTTP Basic，用户名和密码就是管理界面里的账号。

**手机要联调的话**，启动时加 `--host 0.0.0.0`：

```bash
uv run yinshu --host 0.0.0.0
```

### ④ 局域网没有公网？

用 Tailscale / Zerotier 组虚拟局域网，或者 frp / Cloudflare Tunnel 做内网穿透。音枢本身不依赖公网 IP。

## 🏗️ 架构原理（1 分钟版）

把音枢想成一台 **「同声传译 + 会议记录员」**：

```
🎙️ 每个客户端说自己的方言（WebDAV 私有格式）
   ↓ 适配器翻译
🌐 统一成同一门"普通话"（canonical-v1）
   ↓ 合并引擎记录
📝 记下"谁上次看到了什么"（基线），这次多了什么、少了什么，合并成不丢信息的笔记
   ↓ 反向翻译
🎵 输出回各客户端的方言
```

```
栖弦 ──PUT──→ 音枢 ──翻译──→ 统一格式 ──合并引擎──→ 存储
LX-X ──PUT──→          ↑                       ↑
澜音 ──PUT──→          └── 每个客户端一份基线 ──┘

                GET 时反向翻译回各客户端格式
```

合并引擎的规则很简单：

- **🗑️ 删除就是删除**：客户端 `updatedAt` 变了 + 缺席 → 引擎移除
- **➕ 加回来就是加回来**：删掉的歌单随时重新建出来，同步即恢复
- **🧬 各有增删就合并**：在场的全部取并集
- **🛡️ 防误删保护**：客户端如果还没拉到别人新加的歌就提交旧视图，引擎识别出来不会误删

## 📂 项目结构

```
yinshu/
├── src/
│   ├── engine/          # 合并引擎（canonical 模型 + 增量合并逻辑）
│   └── hub/             # 同步服务（FastAPI + WebDAV 门面 + 适配器）
│       ├── adapters/    # 每个客户端一个适配器文件（cyshine.py / lx.py / ceru.py）
│       └── store.py     # 存储 + 备份恢复
├── tests/               # 146 条测试（引擎层 + HTTP 集成 + 多空间）
├── webui/               # 前端 Vue 3 工程（dist/ 已构建好，随仓库一起）
├── run.ps1 / run.sh     # 一键启动（自动装 uv + 配依赖，Windows / Linux / macOS 通用）
└── config.json          # 账号/空间配置（首次启动自动生成）
```
